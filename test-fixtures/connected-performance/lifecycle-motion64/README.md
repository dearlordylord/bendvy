# Lifecycle Motion64 ordinary adoption consumer

This fixture retains the Lifecycle LC2 Motion business callbacks, four actual
Local registrations, plain component storage, six scheduled stages per iteration,
and full physical/canonical observations. Registration adoption derives metadata
and routing around the existing callbacks; it does not replace App replanning,
validation, scheduled dispatch or barriers with a direct Local loop.

Runnable noncore sources were recovered from commit
`ddd23228f2e5ddd79cd13bf3ce0a8960438af630` in the qualified Lifecycle method
worktree. Imports are rebased to this repository's current public core. The
independent model is maintained separately and must reproduce the original LC2
Motion64 stream before sealing this fixture's complete two-world expectations.

The original callback owns Frame arguments, returned outputs, capture recovery,
and failure handling. No new generic argument, retry or output-drop policy is
introduced. Foreign-world results remain role-specific observations.

The adoption module exposes static function-valued factories. The consumer names
fold/plan/dispatch aliases and composes them through the existing public pair and
after-barrier functions. No binding record or runtime function cache is used.
The pilot uses the approved connected-clock elapsed-nanosecond seam, preserving
its original measured work and both FORCE writes inside the interval. The TS
reference preserves its original business and synchronous writeAll transport,
changing only performance.now to process.hrtime.bigint. Complete warmup output
precedes fresh sample world creation. Existing TS RSS sidecars remain whole-process
high-water observations including warmup. Semantic runs make no clock-accuracy,
performance or per-world RSS-reset claim.
