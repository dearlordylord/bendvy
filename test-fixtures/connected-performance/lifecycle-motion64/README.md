# Lifecycle Motion64 ordinary adoption consumer

This fixture retains the Lifecycle LC2 Motion business callbacks, four actual
Local registrations, plain component storage, six scheduled stages per iteration,
and full physical/canonical observations. Registration adoption derives metadata
and routing around the existing callbacks; it does not replace App replanning,
validation, scheduled dispatch or barriers with a direct Local loop.

Runnable noncore sources were recovered from commit
`ddd23228f2e5ddd79cd13bf3ce0a8960438af630` in the qualified Lifecycle method
worktree. Imports are rebased to this repository's current public core. The
independent model is maintained separately and must reproduce the original LC2
Motion64 stream before sealing this fixture's complete two-world expectations.

The original callback owns Frame arguments, returned outputs, capture recovery,
and failure handling. No new generic argument, retry or output-drop policy is
introduced. Foreign-world results remain role-specific observations.

The adoption module exposes static function-valued factories. The consumer names
fold/plan/dispatch aliases and composes them through the existing public pair and
after-barrier functions. No binding record or runtime function cache is used.
The pilot uses the approved connected-clock elapsed-nanosecond seam, preserving
its original measured work and both FORCE writes inside the interval. The TS
reference preserves its original business and synchronous writeAll transport,
changing only performance.now to process.hrtime.bigint. Complete warmup output
precedes fresh sample world creation. Existing TS RSS sidecars remain whole-process
high-water observations including warmup. Semantic runs make no clock-accuracy,
performance or per-world RSS-reset claim.

The finite controls recover the independent four-case registration fixture from
commit `728110b98dafad70e0ef077fce27012629949b9f` at
`experiments/public-api-usability/health-v2/existing-registration-controls`.
Only import rebasing and leaf metadata-function factory calls change. The
original complete 300-byte expectation is retained: successful ordered callbacks,
logical failure after the first callback, refusal of the actual other leaf's ID,
and genuine foreign-world registration admission refusal. The caller still owns
its callback failure and affine token-return policy. These controls establish
routing and owner preservation for this finite fixture; they do not introduce or
requalify a new component access boundary.

The unchanged delegate modules `ordinary-app-existing-execution`,
`ordinary-app-execution-recipe`, `captured-schedule-composition`,
`ordinary-app-run`, `schedule`, and `schedule-provision` are byte-identical to
that historical control epoch. This supports reuse of their established
identity/routing behavior, without claiming that the entire historical core or
all authority scenarios have been requalified.

The Bend entry is `method/pilot.bend`, with arguments
`64 64 warmup.ns sample.ns`. The Node 24 entry is `reference.mjs`, with arguments
`64 64 warmup.ns sample.ns warmup.rss.json sample.rss.json`. Paths must be fresh
and private. `model/EXPECTED.json` binds the complete shared and separate
foreign-role streams. This fixture's semantic correspondence does not establish
clock accuracy, performance ratios, full-matrix qualification or a new #28 result.

Runtime inputs support counts `64`, `256`, and `1024`, with `64` iterations.
The directory name retains the qualified 64-case baseline. Larger inputs require
their independently sealed complete role oracles; accepting an input does not
qualify that matrix case. The count guard is the only TS business-entry change;
the admitted 64-case executes the same callbacks, observations and transport.

Both schemas now have complete semantic correspondence at 64, 256 and 1024
entities, with 64 iterations, in JS, Native and TS. Current-writer Bend checks
cover every size. TS256 reuses exact unchanged consumed sources and guarded
receipts; TS64 retains the explicitly equivalent 64-case admission path after
the count guard was widened. Corrected TS1024 successors bind both the Git
executable and source manifest. Both default 64-case gold hashes are unchanged.
These are semantic results, not the rotated comparative performance matrix.

Tuple transport now writes at most 64 rendered U32 pieces per output chunk
after the clock has ended. Prefixes, brackets, comma-space separators and the
final newline remain unchanged. Encoding, forcing, callbacks, owners and timed
work are unchanged. This bounds the additional text buffer, not retained scalar
lists or the total process heap.
