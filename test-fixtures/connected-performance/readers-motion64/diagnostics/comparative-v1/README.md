# Readers Motion64 comparative adapter

This private adapter preserves the original Readers workload and public operations while separating expected-state verification and private snapshots. The accepted semantic fixture and shared ECS source are unchanged. Runtime and comparative qualification are pending.

The original three Local registrations and two reader providers remain persistent owners in the ordinary App. Their preparation, validation, transaction completion, rollback branches, capture increments, reader commit/release, cursor deltas, phase predicates, barriers and execution order are unchanged. The private `Frame.facts`, Tx-list counting/World rendering, stored query/read-through cursor copies, running-context rendering and provider/context before/after rendering are absent. Actual cursor state and prepared deltas remain owned by the original reader path.

The common carrier retains all 280 original records: seed actors, 84 actual reads, 194 stages and the final full rows/Ledger observation. Every actual reader query, Added/Changed projection, Ping `all`/`lagged`, removed `all`, despawned `all`, update lookup/read/write, remove/despawn command and final public query/resource read remains. Final logical-unread arrays in the TS semantic report were expectations, not operations; they are omitted without adding an empty read or callback.

The Bend public supplement contains `seedOutcome`, chronological `locals`, `reads` and `schedules`. Local records retain actual registration ID, operation, status and the returned business Frame (count, iteration, transient handle and reservation history). Read records preserve the full prepared public view, including the real Bend removed/despawned lagged values. Schedules retain actual namespace, name, ordered steps, requirements, execution status and observations. The TS public supplement contains each actual tick outcome and each update lookup's full old Main payload. Unsupported TS removed/despawned lagged fields and private cursors are never invented. Role-specific supplements differ because the original public operations differ.

TS retains the actual Fast/Slow outcome listener needed to populate common read status. Original success/continuation guards remain; expected world maps, expected cursor tracking, assertions comparing payloads with generated expected state, private debug dumps, diagnostic frame/tick/missed capture and SHA work are absent. Actual assertions' public input reads are retained in complete carriers. Actor-identity and encoding guards remain.

Both complete common and public carriers are materialized, encoded and folded before the end clock. Both FORCE lines are accepted before that clock. Full carrier transport and raw actor maps follow the clock. Warmup completes its transport before the fresh measured world is created. Source-derived models must preserve the accepted complete common records before deriving new role supplements. No speed, clock accuracy, reset-child RSS, seven-rotation or numerical qualification follows from this adapter.
