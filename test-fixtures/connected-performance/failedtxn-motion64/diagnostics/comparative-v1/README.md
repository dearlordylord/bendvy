# FailedTxn Motion64 comparative adapter

This leaf separates verification and private diagnostics from the accepted semantic consumer. It has not yet qualified a runtime or a comparative cohort. The accepted consumer, method, reference, models and shared ECS source remain unchanged.

The adapter imports the original `motion-callbacks.bend` and `motion-grants.bend` directly. Their business body, operations and declarations are unchanged. Local/Reader/Dispose specializations omit the private TxFacts field and observer capability entirely. They preserve transaction begin/finish, rollback, the actual output/error variants, rejected affine payloads, Local capture increments, reader prepare/commit/release and cursor deltas. The existing registration sequence, nine adoption factories, owner tree, phase predicates, App validation/replanning, barriers and public reads remain reached.

The first original boundary query and Main lookups produce detached full `PublicBoundary` records. The existing repeated common-capture queries remain separate and produce the exact original 965-record common carrier. Public App.describe results remain actual schedule records. Before clock end the adapter materializes, encodes and folds both complete carriers and accepts FORCE and PUBLIC-FORCE output. After end it writes complete TUPLE, PUBLIC-TUPLE and ACTORS lines. It creates a fresh warmup world, completes its transport, then creates a fresh sample world.

Bend's supplemental record is `{boundaries:[PublicBoundary],schedules:[Schedule]}`. Each of the 256 boundaries retains iteration, phase, all ordered rows, pendingA, latestFailed, retryB and allFailed with actual access variants and full returned fields. Each of the 385 actual schedule results retains namespace, name, ordered steps, requirements, failure and observations. Private world/allocator/queue/owner snapshots are absent, including their capture work.

TS's supplemental record is `{callbacks:[CallbackPublic],publications:[PublicationsPublic],boundaries:[PublicBoundary]}`. It retains the first lagged read and two post-write readbacks formerly used by B assertions, the first publication all/lagged reads, every successful lookup's full projected row, and all three actual boundary Ledger reads. It adds no queries to mimic Bend. The runtime debug listener remains only where it supplies actual common outcome/error values. Expected-state construction, independent assertions, private frame/tick/missed diagnostics and diagnostic SHA work are absent. Identity/encoding guards and source-pin checks remain. These supplemental carriers have separate role gold because the original public read strategies differ.

Independent source-derived gold must reproduce the unchanged common carrier first, then derive both full supplemental carriers from the existing operation model and actual source calls. Source checks use pinned private Bend2.0.35 resources and Node24. No runtime launch is authorized by this README. Clock units, seven rotations, reset child RSS, numerical decision margins and final performance gates retain their existing separate qualification requirements.
