Current finite JavaScript/Native observations, independent expected output and same-World worker evidence are recorded in [ORDINARY-STAGE.md](ORDINARY-STAGE.md), with their limits; they do not by themselves declare complete GH82 acceptance.

In particular, a caller cannot gain entity authority merely by constructing one of these numeric domains.

Source checking this binding is not evidence of backend concurrency or evaluated values.

## Next integration interfaces and remaining work

The full-schema interpreter traverses the actual full Layout and canonical product together. Validated routes select `ColumnSlot<S,Layout.stored(layout,route),Layout.key(layout,route),Layout.origin(layout,route)>`. Admission prepares per-family recipes, unions grant domains, accounts for predicate-examined rows and structural membership dependencies, excludes conflicts, then cuts mutable owners. Read/read sharing uses structural cached Data after admission; an overlapping live read/write remains a conflict. An explicit old cache capture cannot replace an ordinary live read.

The interpreter derives `With` and `Without` invocation upper bounds from captured storage membership, separately from per-operation value-predicate matches. Optional-only enumeration uses captured live handles, not capacity or occupied allocator slots. General multi-family query shapes, optional writes, broader ordinary count/single/get results and schema-wide failure reconstruction still need integration consumers.

`Build.general_output_query` registers one `WriteRows` declaration and specializes its output type, split, merge and row body before runtime. The resulting `GeneralOutputWriter` exposes the ordinary read and modify operations plus `traverse`. The row body receives a genuine schema-typed handle, the declared view, the actual affine component owner and one output partition. It returns the updated component owner, the output partition and an optional row error. The traversal returns the final output owner with its report. It retains row writes and the returned output when a row reports an error. The ordinary consumer derives detached gameplay effects separately from source rows, then applies those effects through serial edits.

The output traversal supports `Sparse` storage in `Serial` and `Parallel` modes. It accepts `AllMatched` or explicit schema-typed targets. Duplicate explicit targets are refused before the row body runs. Invalid, stale, foreign, absent, excluded or out-of-range targets return `LayoutRefused` with the output owner. `Whole` storage and `SerialWhere` or `ParallelWhere` traversal modes also return `LayoutRefused`. The query bound remains a declaration property; `With` and `Without` bounds are used by the ordinary consumer.

The ordinary consumer registers two systems in one World and runs the schedule twice on that same World. The left system reports a retained body error on both runs, and its right peer succeeds on both runs. Its seven-mode snapshot also covers absent, excluded, foreign, stale, zero and outside target attempts.
