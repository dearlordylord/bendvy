# S-PERF-NEXT — recover the connected performance and measurement gates

Draft follow-up to #20, full-core parent #1. Independent Spec review permits publication as a blocked follow-up; ready state requires the listed design and measurement prerequisites. This is one bounded design/evaluation package; no production layout, numerical threshold, new law or dependency is approved.

## Problem

The connected direct-ID affine-column candidate passes finite ECS behavior gates but JavaScript remains slower than pinned bevy-ts and Native speedups are inconsistent. Historical high-water/tombstone scans remain. Larger Readers measurement children exceed the five-second protocol, and short native intervals cannot substantiate precise ratios. Active transaction occupancy at actual workload boundaries is not fully observed.

1. Freeze #20 exact source/evidence, including all negative attempts. Design one bounded improvement with explicit affine Type ownership/return paths and independent review before implementation. Keep complete field/effect validation and equivalent common observer forcing; diagnostics outside the interval must not remove authored work. Seven rotated fresh samples, raw values, variability, ratios only after semantic gates, independently reset child peak RSS. 4. For every `resolutionLimited` case, preregister a longer identical batch/work on all three backends before collecting replacement samples. Revalidate complete observations and collect seven rotations. Return only when resolution uncertainty is below the separately approved comparison margin. A shared protocol change must be reviewed explicitly; raising one backend's deadline is not a fix.
5. Expose owner-preserving diagnostic hooks for actual workload active-transaction staged commands/events, inverse and mark peaks. Sample before commit/rollback/drain. Keep stored-reader and running-reader cursor/unread/lag distinct, physical batches/values separate from cached counts, and unavailable metrics explicit. Counter mutants must compile, change actual metrics and be detected while authored outputs remain unchanged. Finite fixture peaks cannot replace workload peaks.
6. Obtain independent Spec/Standards reviews and report every capability/size outcome. Native substantially faster and JS at least comparable remain product goals; request numerical thresholds explicitly before making product acceptance claims. Production adoption is separate. A negative research result requires exact failed capability, reason, concrete next design and return conditions; it does not unblock simulation/application integration.
