# JavaScript owner transport: pinned language/compiler findings

Scope: read-only investigation of Bend2 commit `a950fd683c0d76f09794078e6174fe98a1492876`; `git -C .references/bend2 rev-parse HEAD` matched. No source/compiler edits, checker runs, proofs, measurements, or dependencies. Findings concern emitted code, not JavaScript engine allocation elimination or performance acceptance.

## Current language

There is no documented general record borrow, field-update, or alias-pattern facility that lets a function inspect a `Type` record and retain its original owner binding. `Type` variables are affine; reusable `+` variables require `Data` ([ownership rules](/workspace/formal-proofs/bendvy/.references/bend2/guide/GUIDE.md:55), [quantities](/workspace/formal-proofs/bendvy/.references/bend2/guide/GUIDE.md:219)). The syntax inventory lists constructors, destructuring, matching, and array updates, but no general record borrowing/update syntax ([terms](/workspace/formal-proofs/bendvy/.references/bend2/guide/GUIDE.md:604), [statements](/workspace/formal-proofs/bendvy/.references/bend2/guide/GUIDE.md:616)). This is a source inspection conclusion, not a proved language impossibility theorem.

An ordinary affine alias `other = owner` transfers ownership; it cannot make both `owner` and `other` usable. Conversely, returning an untouched owner parameter uses it once and is valid in principle. Reading `cached` by destructuring `Cache{raw,+cached}` consumes the record binding and leaves its fields, so that pattern requires rebuilding the record when returning its owner. Only the cached `Data` field may be duplicated ([actual cache declaration/getter](/workspace/formal-proofs/bendvy/experiments/fivehour-candidate/JS/experiments/s-integrate/cache.bend:3)).

Arrays have a special ownership-preserving API: reads return the array beside a `Data` element, and writes return the same mutable array ([array contract](/workspace/formal-proofs/bendvy/.references/bend2/guide/GUIDE.md:185)). The `a[i] <- v` syntax lowers specifically to `Array.set`, and `a[i]` to `Array.get`; it is not a generic record update ([parser](/workspace/formal-proofs/bendvy/.references/bend2/bend2/bend.ts:2054)). This does not permit copying arbitrary affine payloads or reading a raw owner as `Data`.

## Current JavaScript compiler

Generic constructor emission returns a fresh object literal with a tag and live fields: `js_expr`, `case "Ctr"`, lines 2962–2976 ([emitter](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:2962)). `js_match` obtains fields through property expressions and passes them to the branch; it does not register the original record as a reusable constructor destination ([match emission](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:3038)). Returning an untouched variable emits the variable directly ([variable emission](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:2942)).

Thus the generic JavaScript path has no constructor-identity reuse optimization for destruct/rebuild of `Held`, `Cache`, `Tx`, `World`, or `MetadataColumns`. Special native representations exist for primitives, arrays and strings; none of those five project records belongs to that table ([native representations](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:253)). Internal `emit_alias` in `js_match` names a JavaScript scrutinee; it is not a source-level borrow or alias-pattern capability.

The native emitter does have allocation-block reuse: `node_fields` retains a consumed node in `fl.spares` on eligible tail paths, and `ctr_build` selects a spare of a matching allocation class ([retention](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:1561), [reuse](/workspace/formal-proofs/bendvy/.references/bend2/bend2/comp.ts:1047)). That mechanism is distinct from the `js_expr`/`js_match` path and is not evidence of JavaScript record identity reuse.

## Concrete source-level opportunities

1. **Fuse validation with the consumer of decomposed fields.** `motion_row` reconstructs `Tx`, `World`, and `Handle` before `motion_checked` immediately matches them again ([producer](/workspace/formal-proofs/bendvy/experiments/fivehour-candidate/JS/experiments/s-integrate/held-adapter.bend:54), [consumer](/workspace/formal-proofs/bendvy/experiments/fivehour-candidate/JS/experiments/s-integrate/held-adapter.bend:50)). Pass the separated affine fields plus the namespace comparison into an internal helper. The successful path can call `motion_taken` without that intermediate reconstruction. Rebuild only where a complete owner is actually needed, including the fallback callback. Keep schema/token validation and ownership transfer intact.

2. **Amortize `Held` and cache reconstruction across a trusted internal session.** Current `motion_get` and `motion_ledger` each rebuild `Held` plus the relevant `Cache` ([getters](/workspace/formal-proofs/bendvy/experiments/fivehour-candidate/JS/experiments/s-integrate/held-adapter.bend:9)). A source redesign can unpack once, run an internal sequence on affine fields and separate cached `Data`, and repack at the boundary. Alternatively, expose an authorized cached `Data` snapshot beside an opaque `Type` owner to a specialized read sequence: getters can return the untouched owner plus that separate snapshot without opening the owner. Mutating steps must refresh the snapshot before another read. Keep raw payloads inside the trusted adapter and preserve the abstract-owner callback boundary. This is a design candidate, not a checked implementation; it changes internal/client plumbing and needs the governing access, schema, write-through-read and confinement controls. Merely adding another outer record or pair leaves reconstruction allocations elsewhere.

3. **Carry metadata fields to the consuming operation.** `metadata_live` reads one array and immediately rebuilds `MetadataColumns` in `metadata_live_done` ([implementation](/workspace/formal-proofs/bendvy/experiments/fivehour-candidate/JS/experiments/s-integrate/storage.bend:65)). Let the trusted caller continue with the returned live array, flag/timestamp arrays, and boolean, then rebuild metadata once at its final boundary. This eliminates an intermediate metadata wrapper where the caller would immediately destructure it; it does not eliminate array/result transport or guarantee a speedup. A larger redesign could keep an authoritative live-membership `Data` index separately, but its synchronization obligation is additional work, not an accepted simplification.

These directions retain `Raw: Type`, affine arrays, and opaque callback owners. They do not require a Data-only component restriction, a general borrowed raw-owner API, or a new package. The smallest first candidate is the validation/field-continuation fusion; session/snapshot changes need stale-cache and negative-control evidence before adoption.

## Separate compiler work and limits

Recognizing unchanged destruct/rebuild constructors and returning the original JavaScript object, or reusing an exclusively owned object while updating fields, would require a compiler change outside source-level adapter work. It needs separate task authorization, careful affine/Data alias reasoning, and regression tests; editing the read-only Bend2 reference is not authorized. JavaScript runtime escape analysis may remove some literal allocations, but was not inspected or measured here.
