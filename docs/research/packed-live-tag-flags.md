# Packed live/tag flags — representation candidate

Research only; no source implementation, checker/build, timing, dependency installation or law/proof approval. Read current #30, SPEC and checkpoint. Recommendation: test **packed World liveness first**, independently of indexed lifecycle metadata. Marker-family packing needs a separate storage seam; batching filters is a later semantic change.

## Source and compatibility

The fetched [Bitlist 1.0.0.0](https://jend.leeeet.dev/src/bend-collections-laws-containers@1.0.0.0/src/containers/bitlist.bend) stores LSB-first bits in growable U32 words, indexed by `i/32`, `i%32`; failed out-of-range operations return unchanged state. Its [Bitset implementation](https://jend.leeeet.dev/src/bend-collections-laws-containers@1.0.0.0/src/containers/bitset.bend) provides `word_get` and `word_put` using U32 shifts/and/or/not and linear Base.Array ownership. These are author-source claims, not Bendvy measurements or verified imported proofs. URL supplies a package version, not an independently authenticated Git commit/compiler version. Web open failed; direct `curl -L --fail --max-time 20` retrieved actual source. Fetched source SHA256: Bitlist `cb2e65b8a04921c7eed038f9e9397c8e66fc0bbc700dbcbf043946262a1ecd9b`; Bitset `c5d854bf6d16418adbfb4f00563f9a8daf84443535027d50e12ba2424a966566`. No package compatibility is established: Bitlist imports Bitset, DynArray and error datatypes; adopting it would require dependency approval and actual five-second checks. Prefer a local minimal representation using pinned Base rather than installing the package.

Pinned compiler reference matches tracked manifest: `a950fd683c0d76f09794078e6174fe98a1492876`. [Base](../../.references/bend2/bend2/base.bend) lines1369–1411 exposes U32 bitwise operations and Nat-indexed shifts. [Compiler](../../.references/bend2/bend2/comp.ts) lines153–170 lowers these to unsigned32 C operations and JS bitwise operations normalized with `>>>0`; shifts >=32 explicitly return zero. JS arrays are ordinary arrays (lines6000–6020), not Uint32Array. `Array.get/set` wrap indices (Base2395, compiler223/4092), so allocation/range checks are mandatory **before** packed access; an invalid ID must never alias a valid bit. Native array access uses flattened element layouts in `arr_op`; no source-level O(log n) tree traversal should be assumed to survive compilation.

## Current seams and constraints

- [World](../../src/ecs/world.bend) owns `live:Array<Bool>` throughout every reconstructing helper. `metadata_valid` checks actual namespace, positive ID and `id<nextId`; `valid` then reads actual live storage. Reservation alone leaves live false; activation changes it. IDs are monotonic, current legal maximum131072 (`nextId<131073`), not full U32 space. ID131072 occupies word4096: **4097 words**, rounded to8192 for power-of-two Base.Array capacity. Bit0 remains unused. Keep entity capacity/depth and word capacity/depth distinct: growth within a word need not allocate another word.
- [Owned Header](../../src/ecs/owned-family.bend) owns the actual live Array and rechecks namespace/range/liveness for every operation. [Workshop owned rows](../../experiments/public-optimized-compose/workshop/owned-rows.bend) detach/reinstall that same owner. Every World/Header/bridge reconstruction must migrate together; no copied mask or cached validity.
- [Workshop schema](../../experiments/public-optimized-compose/workshop/schema.bend) stores Enabled/Locked singleton tags as ordinary generic Columns. There is no separate authoritative tag-mask seam. [Component.has](../../src/ecs/component.bend) invokes `get`, and [Compose.family_match](../../src/ecs/compose.bend) invokes its projection. A legal `C -> C & V` projection may change actual payload even for a Data family. A mask-only presence shortcut would skip observable work. Packing must preserve projection calls and arbitrary affine Type owners; it cannot globally equate Data components with empty tags.
- [Commands](../../src/ecs/commands.bend) distinguish liveness-only despawn from gameplay despawn-with-clear; [structural](../../src/ecs/structural.bend) keeps incoming owners in deferred closures. Update masks when actual effects execute, never at queue time. Foreign commands retain queues and owners. Existing transaction inverses restore payload/stamps in order; World clock advancement is retained. Packed tag state, if added, must follow actual insertion/removal/refusal/rollback, not become a second unsynchronized authority.
- `World.handles` visits IDs and returns ascending order. Representation-only experiment retains traversal and per-operation checks; no word-level scanning, filter intersection, callback reordering or predicate/projection elision.

## Migration plan and raw-constructor compatibility

Indexed lifecycle metadata is the first major implementation; flags remain a separate later candidate. A direct field replacement is **source incompatible**: `W.World{...,Array<Bool>,...}` and `F.Header{...,Array<Bool>,...}` are exposed constructors, and existing controls construct them. Replacing their field type by a packed owner rejects those callers. Retaining the old Bool array alongside packed words introduces two live authorities; copying once into Header or reading a cached Boolean violates actual per-operation validation. Packing/unpacking on each query enter/leave performs linear conversion and loses the proposed mechanism.

A possible additive migration preserves the old constructor exactly and adds an alternate constructor to the **same World type**, whose live field owns packed words and separate word capacity/depth. Existing `W.create` continues producing legacy `World`; an explicit `W.create_packed` produces `PackedWorld`. Header similarly retains legacy `Header` and adds `PackedHeader`. A Header/World owns exactly one representation at a time, and enter/leave reconstructs the matching variant without conversion or duplicate arrays. Runtime-world ownership and pending/undo closure types remain the same World type. This is a candidate design, not a checked Bend declaration or approved constructor confinement.

Implementation steps before executing this candidate:

1. Add minimal owner-returning packed get/set/grow primitives and a representation-sensitive World dispatch seam. Both variants must obey identical namespace/ID checks before accessing storage. Preserve entity capacity/depth independently from packed word capacity/depth, max-ID handling and unused padding. All reconstruction helpers in World and Component must handle both variants; Registration, Removals and Workshop owned rows also directly destructure World today. Do not silently fall through, repack, or assume that all worlds come from the selected factory.
2. Add Header dispatch and update owned-row entry/leave for both actual representations. Replace Component's optimized direct live-reader seam with representation dispatch, preserving projection invocation, fallback, metadata validation and arbitrary Type payloads. Every ownership path returns its received representation. Raw legacy World/Header construction remains supported with unchanged field types and all old controls; new packed raw constructors remain forgeable and receive no universal validity guarantee.
3. Review the source-compatibility boundary explicitly. **Old single-constructor pattern matches are not guaranteed compatible with an added variant.** They may fail checker coverage or reject a PackedWorld at runtime; this remains untested until concrete source exists. Existing callers that inspect only legacy constructors may continue receiving legacy values through `W.create`, but that does not prove arbitrary old pattern code can accept the alternate variant. A compatibility API must offer explicit legacy extraction/observation if required; converting to legacy is an explicit boundary cost, never an unmeasured hot-path bridge. If unchanged legacy pattern source must compile universally, a distinct additive PackedWorld type and typed provider adapter may be necessary instead; that is a larger migration, not transparent substitution.
4. Freeze old API replay plus packed/full-owner controls before measurement. Legacy creation must never opportunistically return packed state. If alternate constructors cannot pass all old public consumers, keep the experiment additive and do not deliver a default representation change under #30.

The frozen `327bec49` Workshop `.bend` files were inspected using `git ls-tree` and `git show`: none directly constructs or pattern-matches `W.World{...}` or reads `Array.get(Bool,...)`; schema creation calls `W.create`. Therefore the existing reviewed candidate-provider overlay can select `W.create_packed` **in candidate schema only**, retain `S.World() = W.World<...>` and all frozen driver/gameplay/observe/main bytes, and exercise packed state through existing typed public operations. Baseline archive and statistical contract stay unchanged. This is contingent on complete dual-variant core dispatch and current old-consumer checks, not established compiler compatibility. The default archived schema continues testing legacy `W.create`, while the selected provider gate must explicitly record the packed factory selection and run complete observations. No benchmark source rewriting or baseline amendment is implied.

Generic tag packing remains outside this first migration. Enabled/Locked are schema-authored ordinary Columns, and projection effects must remain. A reviewed future marker storage seam must explicitly distinguish actual singleton tags from arbitrary Data/Type component families and integrate lifecycle/removal/rollback authority; a bitmap cannot simply replace `Component.has` or `Compose.family_match`.
