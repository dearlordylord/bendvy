# Delivery process review

Tracking issue: [#69](https://github.com/dearlordylord/bendvy/issues/69).
User-approved process simplification, 2026-10-09. This is a record for the user’s
later assessment, not an agent experiment, deadline or additional work assignment.
The user chooses when to review results. The implementing agent continues its
existing goal through the shortened workflow without a timed trial or special report.

## Changes applied

- Shortened agent workflow and check policy; technical runner details are disclosed
  only when authoring or changing runners, bindings, controls or verifiers.
- Existing reviewed feature runners use one independent final code/evidence review.
  New/changed runners, compiler experiments and comparative performance plans retain
  independent launch review. Contracts and all existing acceptance gates remain.
- Reuse source-matching qualified evidence and run affected checks; batch compatible
  integrations for the unchanged general regression gate.
- Keep coordination concise and prioritize completing approved capabilities.
  Preserve live assignments, in-flight runs and unrelated edits.
- One evidence package/final report per delivered capability or integrated slice;
  automatic receipts retain intermediate attempts.

## Expectations for later user assessment

More capabilities should reach actual acceptance with less manual preparation,
repeated admission, reporting and redundant checking. Claims must retain complete
source-bound semantic/backend evidence and independent final review. No scope,
ownership, numerical gate or proof-approval requirement is relaxed.

At a time chosen by the user, compare the existing coordination table, owning
issue updates, Git history and normal receipts: completed capabilities, cleared
acceptance gaps, integration/review rework, repeated checks and visible waiting
reasons. Use available timestamps; unknown active-time attribution stays unknown.
No new telemetry, periodic reporting or worker deadline is required.

Baseline: history and current evidence at the user’s handoff. The implementing
coordinator may commit the selected process changes together with a concise normal
handoff; this review task does not require a separate start ceremony.

Retain simplifications that help delivery without evidence gaps; adjust those
that produce material rework. The review is not full-core acceptance, a new goal
or a project completion estimate.
