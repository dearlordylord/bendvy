## Blocking preflight issue

`prototype_split_motion_shape` allocates `Array.new(U32,depth,0)` before the buffer guard checks either physical Main size or physical buffer size. `Rows.depth` is publicly constructible metadata and may be oversized/inconsistent with a physically small Main. Thus the new buffer allocation can fail-stop or consume unbounded additional resources where the original query/fold could complete. The installed Native `blk_new` rejects depth beyond its runtime limit; smaller oversized values still initialize exponentially many cells. This is a concrete source-backed failure risk, not an executed counterexample in this review.

Before candidate admission, a new immutable version must reject unsuitable metadata before allocation or derive bounded buffer depth from actual physical Main size/capacity, with overflow/zero cases routed to the original path before evacuation. Fresh oversized-depth, undersized-depth/ID size and undersized physical Main controls must exercise that preflight. Merely inspecting Array.size after allocation does not fix this issue. Author and root were notified immediately.

As previously documented, exported malformed detached bundles can violate count/list/initialized-ID alignment; checking Nil/count cannot recover IDs already lost. Safe finite scope remains private producer-to-consumer confinement. Complete true-old, order, namespace, nonidentity recovery, pending Pair, immutable cached Data and authority gates must be newly source-bound; no concrete-v3 gate transfers.

## Conditional saturated drain redesign after v12 cost rejection

Root independently observed v12 full65 correctness but substantially worse allocation totals; this review has not executed those counters. Preserve v12 as a rejected performance mechanism, with no timing admission. A narrower new source probe may carry `DrainState{buffer,count,fold}` and make recursion structurally direct: `loop(rest,step(owner,state))`. The loop retains the affine rest outside step, removing its capture in the three curried continuation layers. No temporary None-ledger Fold should be constructed.

The success step must be a named saturated function. Match the complete incoming Fold with Some ledger, read ID[count−1] through Array.get, and use a second named saturated pair eliminator carrying every original context field explicitly. It passes the original owner, ledger, namespace/id, columns, metadata, journals, pending commands, mode, pings and total to the unchanged taken helper, then returns DrainState with the returned Fold and decremented count. Evaluate the ID read before that unchanged callback invocation. Do not replace this helper with a closure capturing rest or affine context.

The loop's LedgerNone branch must precede the success step/ID read and restore the complete current owner plus rest using the original buffer/count, then invoke the unchanged recovered cursor continuation with original selected/full context. Nil returns its Fold and discards the now-unused buffer; it must not read a nonexistent ID. Initial preallocation and missing-ledger fallbacks remain v12's corrected routes. Existing private producer alignment is still required; malformed detached bundles remain outside a universal recovery claim.

Conditional design approval is for layout/allocation-first diagnosis only. DrainState wrappers, explicit field transport, Array pair elimination and remaining Q recovery closures may still allocate/seal; count all of them. Fresh zero/one/multi-ID, LedgerNone/nonidentity recovery, true-old/full context and omission/order controls are needed after any source revision. No implementation, performance adoption or callback-algorithm replacement is authorized by this review itself.
