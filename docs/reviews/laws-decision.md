# T11 laws: decision after source research

Withdraw the existing fourteen-law bundle as the public ECS-law approval proposal. Preserve its statements and revision-specific falsification results as historical experimental evidence. Several equations are useful auxiliary lemmas; none currently establishes the advertised public ECS transition. A stronger replacement should be drafted and falsified before a new request for approval. This decision approves no law and authorizes no ECS proof.

This adjudication is based on the completed [Luna source audit](laws-source-research.md), especially its fourteen-row evidence matrix and Bend consequences, together with [SPEC](../SPEC.md), [T11 laws](../../experiments/t11/LAWS.bend), model, independent specification and README. Each decision below refers to the identically named evidence-matrix row. Source paths and lines below use the audit's verified pins; they are not claims of newly executed reference traces. I ran `bend version` (2.0.34) and read `bend guide`. The pinned Bend source is 2.0.35; it is not the installed binary's proven source identity. No checker, proof, benchmark or new trace was run for this decision.

## Governing semantics

The complete pinned bevy-ts core remains the behavioral target. Rust Bevy supplies conceptual guidance and secondary comparisons. Its storage iteration, automatic deferred barriers, read-time cursor advancement and lack of TS-style automatic system rollback do not cancel agreed TS contracts. Adopting those behaviors would require an explicit scope change. Native Bevy supports the concepts of entity identity, reservation distinct from liveness, component selection, deferred commands and independent readers; the precise timing and ordering must still come from the selected target.

Preserve the approved foreign-world lookup divergence: a handle from another runtime world returns `MissingEntity`, including a same-schema, same-local-ID collision. The namespace must originate in world creation. A fixture number or supplied `False` does not establish that property. The SPEC explicitly approves the lookup result; rejection of foreign command authority must also be enforced, but do not infer from that sentence an approved new public command error/ignore result. Record the chosen observable result against the existing command contract when drafting its law.

The old statements are not all false. Their main defect as a package is the distance between their actual subjects and the desired guarantee. Truth of a helper's defining equation is useful only when its callers, decisions and observations are also constrained. Calling a statement a model law does not remove those obligations.

## Strongest first corrected package

Start with a connected bounded transition package, not fourteen unrelated easy equations. Its domain is a declared admissible model of world creation, fresh reservation, pending/live distinction, local/foreign lookup, command publication/application and query observation. Define the observation vocabulary and independent command semantics first. Add the three cursor helper statements as explicitly separate executable-function candidates; the transactional reader wrapper package follows with its own state and transition model. This is a staged proof effort within the full core, not a Data-only product boundary.

For each public observation, include both exclusion and positive behavior: a valid local lookup succeeds; an eligible query row appears; an in-capacity reservation succeeds; a queued spawn becomes live at the barrier; a successfully consumed reader advances; a failed reader retries the same retained messages. Supply reachable witnesses for every premise and mutations of the real decision path. An always-empty query, always-Missing lookup, always-reject allocator, no-op flush or permanently frozen reader must fail the proposed package. Guard-false literals and errors in an unrelated helper do not suffice as those controls.

In Bend, retain Data snapshots for mathematical observations while consuming and returning the actual affine world through its API. Do not mark an owned world or affine payload reusable to state both sides of an equation. A projection operation may return the owner together with a Data observation; erased specifications or relations can describe that ownership-preserving transition without assuming a runtime clone. Inspect the concrete interface before choosing its law encoding. Array access must preserve its owner and respect bounds; the installed guide warns that indexes wrap. Closed templates or explicit threaded state must respect repeatable-system constraints; arbitrary affine closures cannot silently become reusable callbacks.

The refinement obligations are concrete: define relation R between a reachable owned runtime state and its model observation; establish R at creation, prove that each admissible runtime operation and its model step return equal observations and related successor states, and preserve admissibility. Then a trace induction can establish universal correspondence for the covered operations. Namespace creation, correct guards, U32 bounds, authorized command targets, query order, reader selection, transaction publication and pending barriers each need their own link. A model proof, a helper-function proof, a finite TS/native/JS comparison and this universal runtime theorem are four different deliverables. None implies compiler/backend correctness or host-IO rollback.

Keep abstract handles confined and require negative checking controls for undeclared access, cross-schema misuse and writes through read. Preserve the previously bounded R-A/R-C1 conclusions when extending their interfaces; do not infer general authority or affine-payload support from a Data projection theorem. Transactions over owned payloads still require a viable restoration design and evidence.

State observable query order and logical command order without freezing linked lists, reversed queues, Nat counters or a storage layout. An implementation may reorganize storage and use efficient indices while preserving the required observations. Ascending-ID query order is a real TS requirement here; loosening it for speed is a scope decision. Conversely, proving input-list order is not a reason to retain list storage. Measure native and JS compiled work, structural churn, readers and rollback against equivalent TS scenarios; laws do not establish performance. Numerical acceptance thresholds still require agreement.

## Action order and approval boundary

1. Mark the old proposal withdrawn and retain its exact historical evidence. Do not relabel prior literal controls as validation of revised statements.
2. Draft the independent transition/observation specification and admissibility relation, with positive cases and named runtime links. Resolve discoverable target behavior from the pinned references; record genuinely unresolved observable choices such as exhaustion and foreign-command result policy explicitly.
3. Implement/falsify precise candidate statements and check meaningful mutants under the five-second checker limit. Run actual reference/runtime checkpoints before labeling comparisons observed. Keep every missing ownership or refinement link open.
4. Present exact revised law IDs and revision, rationale, valid-premise controls, killed mutants, proof sketches and remaining limits for approval. Only then write ECS proofs and run their mutation gates.
5. Expand the connected model/runtime obligations to transactions, reader retention, composition, relations/scopes, state machines and remaining core, alongside storage/performance evidence and the planned simulation.

Reclassification, correcting misleading labels, adding missing technical guards and drafting/falsifying stronger candidates do not require repeating the already granted permission to investigate. Approval is still required for the particular laws before proof, new dependencies, numerical performance thresholds, and actual scope changes: replacing TS contracts with native Bevy behavior, changing observable order/rollback/retention, adopting a new exhaustion policy, or restricting production payloads to Data. The foreign lookup divergence already has approval and should be implemented and tested accordingly; that approval does not approve this replacement law package.
