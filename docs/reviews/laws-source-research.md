# T11 candidate laws: source audit

This is source research for review, not approval of any T11 law. I applied the repository research workflow and the Bend law-review guidance; I did not edit laws, proofs, runtime code, dependencies, references, or issue state.

## Source identity and scope

The checked-out references match `sources.json` exactly: Bevy `ad678262ce53b5d142fe49ee5e08caff6f00ab60`, bevy-ts `3040a3b2a3f28fa8554d856f9ccb6bf5433fa334`, Bend `a950fd683c0d76f09794078e6174fe98a1492876`. The installed compiler reports `bend 2.0.34`; I ran `bend guide` and `bend base`. The pinned Bend source reports 2.0.35 (`.references/bend2/bend2/main.ts:33`, `.references/bend2/CHANGELOG.md:6`), so its source is a cross-check, not authority over the installed 2.0.34 compiler. The Bend language statements below were confirmed against the installed commands; corresponding pinned-source locations are included for review.

The governing behavior is the pinned bevy-ts core. Rust Bevy is a conceptual, secondary reference. The approved divergence is explicit: same-schema handles from a different runtime world must return `MissingEntity`; the TypeScript reference can resolve a colliding local numeric ID (`docs/SPEC.md:68`, `experiments/t05/run.py:95-99`). That decision is not approval of T11’s candidate laws.

The 14 statements in `experiments/t11/LAWS.bend:8-78` split into eleven laws over a small pure model and three laws over Data cursor functions. None calls the owned runtime wrapper, schedule executor, or public TS API. T11 itself says these do not establish wrapper correspondence (`experiments/t11/README.md:5-6,65-85`). The bounded controls/mutants described in that README remain finite model evidence; they do not close this gap.

## Bend consequences for all 14 statements

The T11 model declares `Row`, `Handle`, `Command`, `World`, `Lookup`, `Selection`, and `Reservation` as `Data` (`experiments/t11/model.bend:3-23`). The T07 `Log` and T08 owned `World` are `Type` (`experiments/t07/streams.bend:3-10`; `experiments/t08/core.bend:4-16`). Bend’s installed guide describes affine use by default, `+` reuse only for `Data`, `Type = Kind(&1)` and `Data = Kind(&2)` (corresponding pinned 2.0.35 text: `.references/bend2/guide/GUIDE.md:55-59,198-225,247-255`). Therefore the first eleven laws say nothing about consuming and returning an owned world; the three cursor laws do not prove that the runtime selects/restores the right affine reader. These are API/refinement obligations, not reasons to restrict production components to Data.

`Nat` is an inductive Data type and its addition/comparison recurse structurally (`.references/bend2/bend2/base.bend:28-30,566-571,607-628`). T11’s slot, world, and next fields use Nat, so their arithmetic does not model fixed-width counters. Bend’s U32 is `Word(32)` (`base.bend:57-58`); `Word.add` returns a same-width word and its carry recursion emits no wider result (`:1213-1249`), so overflow is fixed-width (inference from the implementation). `reserve_projection`/`bounded_reservation` need explicit bridge laws from reachable U32 state to Nat and back; a Nat proof alone cannot close the U32 boundary. Recursive list filters and erasures are structurally decreasing and suitable proof subjects, but a proof establishes only the exact function/law pair supplied; it does not validate backend execution or whole-runtime refinement.

## Approval decision support

The clearest weak statements are the supplied-Boolean guard/reservation/failure branch laws (`foreign_lookup_guard`, `foreign_command_guard`, `reserve_projection`, `reserve_rejection`, both failure-position laws), the identity implementation law `tick_preserves_pending`, and the helper-sharing projection `flush_fifo_projection`. The query/despawn oracle pairs are more substantive than those branch laws, but still use copied list algorithms and have no runtime linkage. None should be described as an ECS runtime law without additional public-wrapper obligations.

The required next review is to name exact candidate IDs and separate (1) model/helper equations, (2) executable-function proofs, (3) finite source-reference traces, and (4) universal runtime refinement. Add the missing helper and correspondence statements before approval; do not silently alter TypeScript’s agreed cursor, skip, order, command-marker, or rollback contracts because Rust Bevy has different behavior. No ECS proof or new law approval was performed in this audit.
