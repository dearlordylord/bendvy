## Source result

No concrete implementation defect was found in the inspected delta. Query retains its complete original byte prefix after removing the single new CP import. The two appended families mechanically specialize only Schema/Main: exact nominal Motion/Health MainSlot owners remain Type and retain their owned Arrays and distinct raw/cache scalars. Aux and Ledger remain Type; Flag and Mode retain their original Data kinds. The generic arbitrary-M route remains available, rather than being narrowed to concrete payloads.

Held-adapter changes only handoff drain/ready carrier types, constructor matches and producer/recovery selections for both schemas. The success branch still passes the consumed owner to the original packed taken helper, same namespace/id handle, and every original context field. All callback/provider/returned/finish implementations, measurement registrations and authored batch algorithms remain unchanged. Descending production/prepend and ascending drain are preserved. The size guard, initial LedgerNone fallback and false-shape original query/fold branch are unchanged. Mid-drain LedgerNone reconstructs the complete current node plus rest, invokes the specialized recovery with unchanged columns, and resumes the original recovered cursor loop with full returned context. No stale detached owner is reattached after that continuation.

The exposed Batch/carrier constructors still do not enforce world-hole alignment or a production confinement boundary. This remains a private experimental route; unchanged prefixes do not establish universal authority or refinement.

## Fresh allocation interpretation

Read-only inspection of the independent worker's `/tmp/bendvy-native1024-concrete-{motion,health}-transport-v1/{evidence.json,analysis.json}` and actual C confirms a narrower result than eliminating owner boxes. Each schema still constructs 4,194,304 MainSlots, concrete handoff nodes, FlatPairs and FlatMarks. Motion surviving slot is `batch.c:8898`, Health `:9309`; these allocate class-fit7/class-fit9 respectively while publishing the reconstructed Some into the columns Array. This corresponds to unchanged HA row-return code, Motion `held-adapter.bend:662`, where returned affine row fields reconstruct the nominal MainSlot for `Array.set`. The successful evacuation edge no longer seals a boxed opaque Main owner, but this does not remove the subsequent row-return slot constructor.

Concrete carrier allocation is Motion C4573 (9 logical words) and Health C4893 (11), both class16. The old generic carrier was class4. Across 4,194,304 updates, the extra12 carrier words cost50,331,648 words; removed4,128,768 RFC cells offset that to the observed net +46,202,880 words (+11.015625/update). Requests and RFC fall by4,128,768, while total constructor counts remain equal after normalizing the carrier tag rename. Observed totals are29,758,407 requests/12,677,438 RFC for each schema, with169,438,223 Motion and202,992,655 Health requested words. These are the independent worker's actual allocation observations, not timing or this reviewer's rerun.

One bounded fallback if raw results show the wider carrier loses is to restore the original generic opaque carrier independently for the affected schema, retaining the same two-phase source algorithm, callbacks, guard and recovery. That is a representation rollback to the verified v8 path, not a claim of another optimization: it trades the owner RFC back for class4 nodes and avoids speculative scalar packing or changes to arbitrary Type ownership. The surviving row-return constructor belongs to persistent column publication, so merely adding an erased helper or changing producer names does not justify claiming its removal. A different persistent storage representation would require a separate design and full payload/recovery gates. No second candidate is proposed for implementation before the raw results.
