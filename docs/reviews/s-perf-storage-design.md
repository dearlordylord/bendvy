# S-PERF indexed-storage architecture review

Reviewed independently at `a5011cd`, before candidate core implementation. Scope: [design](../design/s-perf-indexed-storage.md), frozen baseline, existing storage/provider boundaries and pinned Bend/Bevy sources. This reviewer authored none of the proposed storage. The Bend LDD review discipline applies; `bend version` reports2.0.34 and `bend guide` was read. No candidate build or performance pass is claimed.

**Verdict: proceed with one bounded direct-ID indexed candidate, subject to the execution gates below.** The decision does not require a separate map/compaction design phase or another routine architecture review. It approves the experimental implementation direction, not a production layout, allocator policy, universal law/proof, dependency or numerical threshold. Incorporate these concrete clarifications in the implementation and design record before integration.

## Representation decision

Mapping committed ID to `id-1`, with independent affine Main/Aux columns and Data metadata, is consistent with the frozen monotone-ID, no-reuse behavior. It eliminates the list search from point operations while naturally retaining ascending query order. Namespace must still be checked independently: a numeric slot is not authority. Reservation consumption must remain separate from committed membership; failed reservations create holes without installing a row. Committed high-water is the greatest installed ID, not the reservation counter or live count. Retaining a high-water upper bound after disposal is safe when every query filters live metadata.

This is not a compact sparse set. The pinned Bevy `ComponentSparseSet` has a dense Column plus entity-to-row sparse mapping; its swap-removal updates the moved entity's mapping (`crates/bevy_ecs/src/storage/sparse_set.rs`, structure near159, removal near399/443). Borrowing that layout now would introduce relocation, ownership and order obligations that direct slots avoid. Growth still needs first/middle/last association controls. Compaction-specific relocation mutants are inapplicable to a candidate that never relocates existing IDs; record that applicability explicitly instead of claiming to have exercised relocation. Severe historical-ID growth remains a known space and query-cost limitation, to measure and retain rather than hide.

A transient Row adapter is acceptable for the existing opaque callback seam. Extract the necessary owners, invoke the callback once, and restore its returned owners and exact metadata. Main-only point operations must not retrieve every component or construct a complete row/list. Query paths may construct one transient row per visited live entity; that is a legitimate initial implementation, with its cost measured. Do not reconstruct all rows around each point read/write, mark update or inverse operation. There is no evidence yet that the candidate meets the performance requirement.

## Required implementation clarifications

1. **Balanced arrays and safe arithmetic are representation invariants.** Pinned Base `Array.size` descends the left subtree and doubles its size; `Array.swap.at` masks the index by `n-1`. Therefore a raw `ANode` is not automatically a valid larger array. Growth must pair two equal-depth balanced halves, maintain identical capacities for Main/Aux/metadata, and construct fresh empty Type slots without copying an owner. Doubling, `id-1`, high-water iteration and capacity comparisons must reject overflow before arithmetic can wrap. Do not infer a valid domain merely from the U32 type. Record the actual supported/exercised capacity and include E11's IDs above65536.
2. **Preflight unsupported placement before consuming anything.** A private rejected-placement result must return the intact store, incoming Main/Aux owners and all pending work. Check representability and required growth before removing a pending command or applying a FIFO prefix. Do not map this failure to public MissingEntity, silently skip the command, drop a payload or introduce a new exhaustion result. For this bounded experiment, a reached unsupported domain is a recorded capability failure at the harness boundary; it is not a successful runtime transition. Actual allocation failure is not promised to be recoverable by a private arithmetic gate. No new public capacity policy is approved.
3. **Keep entity liveness distinct from component presence.** Existing Row components are optional. A live entity with no Main is not a tombstone; MissingEntity and missing-component outcomes must remain distinct. Metadata consistency means agreement with these legal states, not `live == Main-present`. The temporary None used for affine extraction must not escape as a committed missing component. Restoring a returned owner must preserve other components, flags and ticks unless that operation explicitly changes them. Query reconstruction must return every extracted owner, including branches that reject a filter.
4. **Growth is representation-only.** It must not stamp changes, publish events, advance readers, consume new IDs or reorder commands. Row insertion/marking remains at the existing deferred/transaction boundaries. Validate rollback across a growth boundary and a failed reservation hole, retaining earlier commits and full payload fields. Keep the current inverse LIFO behavior; the baseline does not justify an unrelated journal-order rewrite.

## Concrete execution gate

Complete the small owned-array canary before replacing the joined runtime storage: checked positives on fresh Type slots and repeated owner-return calls; Native/JS growth across several powers of two; first/middle/last fields and unrelated owners preserved; private rejected placement returns every owner and unchanged queue/store; zero/foreign/out-of-domain/tombstone controls cannot alias. Pair it with intended compiler negatives for copying/incorrect ownership and compiling semantic wrong-slot/growth/order controls. A compiler rejection of owner duplication is an ownership negative, not a compiling semantic mutation kill. If this gate fails, retain its exact failure and adjust the primitive, without switching payloads to Data.

After that gate, proceed directly with the isolated candidate overlay and the already specified full trace/access/retention/mutation and five-workload evaluation. Preserve exact full observations, quiet FailedTxn validation, Readers timing alignment and actual occupancy/lag instrumentation. Measure high-water scan costs and memory under churn; repeated indexed extraction may cost tree traversal rather than constant-time machine array access. Keep all failed deadlines, and distinguish candidate source/build evidence from the immutable baseline. No performance claim follows from the primitive canary.
