# Как устроен bevy-ts Сандро

Исследован checkout `3040a3b2a3f28fa8554d856f9ccb6bf5433fa334` в `.references/bevy-ts`. Rust-сравнение относится к Bevy `ad678262ce53b5d142fe49ee5e08caff6f00ab60` в `.references/bevy`. Это анализ исходников; тесты и benchmarks в этом исследовании не запускались.

## Главное

Сандро сделал самостоятельный ECS runtime, вдохновлённый Bevy, с API, адаптированным к TypeScript. Репозиторий прямо описывает Bevy как reference for the problem space, а не требование копировать engine-owned ergonomics. Поэтому правильный аналог для Bend2 — перенос понятных ECS-семантик с собственным представлением мира и безопасным интерфейсом, а не механический перевод Rust или TS. [README](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/README.md), [правила проекта](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/AGENTS.md).

## Фактический scope

| Область | Реализация и границы |
| --- | --- |
| Schema и descriptors | Закрытый реестр components, resources, events, services; композиция fragments; bound `Game` API. Identity descriptor — `(kind, name)`, а не Rust TypeId. Дубликаты отвергаются при авторинге и при runtime-проверке. |
| Entities и commands | Spawn/despawn, insert/remove, staged drafts, storage-safe handles, entity scopes. Handle требует fallible lookup и не доказывает liveness. |
| Queries | Read/write/optional selections, presence/absence, added/changed, lookups, relations. Read cells глубоко readonly на уровне типов; запись через cells, а не произвольную мутацию пользовательского объекта. |
| Systems и schedules | Явная декларация доступа; последовательное исполнение в authored order; вложенная композиция, условия запуска, явные `applyDeferred` и `applyStateTransitions`. |
| Resources/services | Resources принадлежат ECS и участвуют в rollback. Services предоставляются host и входят в requirements; побочные эффекты host-сервисов нельзя считать транзакцией ECS. |
| Events/lifecycle | Независимый cursor каждого читающего system, retention до прохождения читателей, ограничение stream capacity и `lagged()`. |
| States | Component state descriptors и global state machines; queued transitions, enter/exit/transition schedules и transition events. |
| Relations/hierarchy | Отдельные source→target и target→sources индексы, проверки hierarchy cycles, relation queries и failures. |
| Composition/tooling | Features с dependencies и ограниченным доступом к schema; snapshot load/save; read-only inspectors; opt-in Debug и devtools sessions. |
| Host adapters | Browser fixed-step loop/input/capture, math values, Pixi node registry/render sync. Они вынесены из core. |

Источники таблицы: [Schema](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Schema.ts), [Query](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Query.ts), [Runtime](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Runtime.ts), [Relation](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Relation.ts), [Feature](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Feature.ts), [packages](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/README.md).

В `packages/core/src` поиск `TODO`, `FIXME`, `not implemented` не обнаружил обозначенных заглушек. Это не доказывает полноту относительно Bevy: это завершённый собственный API, с иными границами. Нет Bevy renderer/assets/audio/UI/scene engine; Pixi — внешний renderer. Нет архетипного storage и parallel system executor Rust Bevy: TS `runSteps` проходит шаги циклом последовательно. Нельзя планировать Bend2 по предположению, что Сандро воспроизвёл полный `bevy_ecs`. [runSteps](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Runtime.ts#L1598), [Rust executors](https://github.com/bevyengine/bevy/blob/ad678262ce53b5d142fe49ee5e08caff6f00ab60/crates/bevy_ecs/src/schedule/executor/mod.rs).

## Что он перенёс, а что перепроектировал

1. **Сохранил модель предметной области.** Entities имеют components; queries выбирают доступ к данным; systems работают в schedules; structural changes откладываются; state transitions и relationships входят в runtime. Это общая семантическая основа с Bevy. [Concepts](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/CONCEPTS.md).
2. **Заменил Rust traits/macros/borrowing на declarative capabilities.** `Game.System` получает точное описание queries/resources/services, из которого выводится callback context. Schedule несёт компактный union requirements; `tick` сверяет provisioning статически, `tryTick` возвращает missing requirements как данные. Сложные условные TS-типы проверяются на boundary, затем нормализуются. [Architecture](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/ARCHITECTURE.md).
3. **Написал новый storage.** EntityRecord хранит массив component values по ordinal, marks добавления/изменения и cached matches. Каждый component имеет множество соответствующих records. Query начинает с самого редкого required component, кеширует matches до изменения membership versions и выдаёт deterministic ascending entity IDs. Это object/array/index design для JS, а не перенос Bevy Tables/Archetypes. [world.ts](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/internal/world.ts), [queries.ts](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/internal/queries.ts), [Rust Tables](https://github.com/bevyengine/bevy/blob/ad678262ce53b5d142fe49ee5e08caff6f00ab60/crates/bevy_ecs/src/storage/table/mod.rs), [Rust Archetypes](https://github.com/bevyengine/bevy/blob/ad678262ce53b5d142fe49ee5e08caff6f00ab60/crates/bevy_ecs/src/archetype.rs).
4. **Добавил собственный failure model.** Minimal synchronous `Fx<A,E,R>` и tagged Result; expected system failure откатывает ECS-owned writes и не публикует events/commands. Предыдущие успешные systems остаются committed. Defect exceptions также вызывают rollback, после чего пробрасываются. Это полезная семантика для Bend, но её следует принять отдельным явным решением. [Fx](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Fx.ts), [runSystem](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/src/Runtime.ts#L1380).
5. **Сделал boundaries видимыми пользователю.** Завершение schedule не flush-ит commands. Нужен явный marker; queued work живёт между ticks. Каждый reader независимо видит changes/events, а переполнение сообщает loss. Это гораздо важнее для совместимости поведения, чем синтаксис API. [Architecture](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/ARCHITECTURE.md).

## Зависимости, примеры и evidence

Core package не содержит runtime `dependencies`; optional peer — TypeScript >=5.9. Он реализует собственный небольшой Fx, а не зависит runtime от Effect. Effect, Pixi, Matter.js и tooling находятся в root devDependencies и используются host/examples/tooling. Browser зависит от core; Pixi adapter — от core/browser. Поэтому ECS в Bend2 можно проектировать независимо от browser/renderer. [core package](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/package.json), [root package](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/package.json).

Есть smoke/concepts, genetics, Pixi games (snake, space-invaders, pokemon, state-machine), platformer и top-down. Top-down имеет отделённую headless simulation и тесты scripted input — подходящий образец acceptance scenario без graphics. Runtime test suite содержит 20 test files, а типовые ограничения отдельно проверяются TSTyche. Bench suite измеряет storage/query/change detection/commands/events/relations/schedule и стоимость TS checker. Это наличествующий тестовый код, а не подтверждение прохождения в нашей среде. [simulation](https://github.com/SandroMaglione/bevy-ts/blob/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/examples/top-down/simulation.ts), [tests](https://github.com/SandroMaglione/bevy-ts/tree/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/test), [bench](https://github.com/SandroMaglione/bevy-ts/tree/3040a3b2a3f28fa8554d856f9ccb6bf5433fa334/packages/core/bench).

## Рекомендации для Bend2 из этого исследования

Первый рабочий срез: headless World → spawn/despawn → typed components → read/write query → последовательные systems → deferred commands + explicit flush → deterministic movement example. Следующий слой: resources, changed/added, per-reader events, relations/hierarchy, state transitions. Snapshots, entity scopes, feature composition и debug можно добавить после стабилизации основных transitions. Это предлагаемый порядок реализации, а не утверждение о возможностях Bend2.

Сохранять следует observable semantics и capability boundaries; TS conditional types, WeakMap query caches, mutable cells/prototypes и массивы `unknown` — детали реализации исходного языка. Для Bend2 нужно отдельно решить closed heterogeneous schema, generic storage, state passing/linear usage, host boundary и цену immutable updates. Авторский подход Сандро показывает, что сначала допустим простой последовательный ECS; parallel scheduling и Rust memory layout не являются условием такого scope.

Критерии acceptance следует брать из поведения: команды не видны до flush; saved handles после despawn дают failure; query order стабилен; разные читатели независимо получают события; failed system не публикует ECS mutations; hierarchy cycle отвергается; state transition происходит только на marker. Эти свойства непосредственно следуют из API и архитектуры выше и пригодны для тестов и будущих формальных laws.
