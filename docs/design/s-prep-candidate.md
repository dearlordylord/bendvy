# S-PREP bounded candidate proposal — unapproved

Source pin `56b72f6`, #22 child of #21. This is one concrete design for independent design/Spec review before implementation. No core, law, proof, dependency or production layout changes accompany it. The source-supported motivation is `candidate/query.bend:read_rows_start/read_rows_go`: queries increment every logical ID through committed high-water; `rows_extract` probes metadata and transfers/restores both affine columns for each live row. This establishes operations performed, not a measured bottleneck. Failed large Readers output phases additionally implicate authored observation/transport work; membership changes alone have no demonstrated deadline remedy.

## One change: ordered occupancy tree with affine structural traversal

Keep direct `id-1` mapping and balanced Main/Aux Type arrays. Add a balanced Data occupancy tree aligned with column capacity: each node caches the number of **live entities**, each leaf records live membership. A node whose count is zero can be skipped; traverse left then right to retain ascending logical IDs. Do not use dense insertion order, a Data copy of payloads, or a mutable callback-visible iterator. Occupancy includes entities with Main absent; Every selection still skips Main-absent rows through existing Main-presence behavior. Flag/Aux and added/changed metadata predicates remain unchanged.

Walk the aligned Main/Aux/metadata trees together, retaining owned sibling subtrees in the recursive reconstruction context and carrying the logical base offset. Each visited leaf is consumed once; the existing rank-2 client receives abstract Main/Aux providers, returns both owners, and the rebuilt leaf receives exactly those returned owners. Rebuild each traversed node once on return. Empty occupancy subtrees are returned unchanged with all their Type owners. This avoids repeated root-to-leaf extract/restore for query rows while retaining indexed point access. The reconstruction context holds Type owners; it cannot be duplicated, exported through Data observations or retained by client callbacks. Public outputs remain the same ordered Data list. No query mutation queue is flushed implicitly.

Point operations retain explicit namespace, nonzero ID, supported-domain, capacity and live checks **before** index arithmetic/array access. Base masked array addressing is not validation. A stale/foreign/zero/out-of-capacity handle returns the existing Missing classification, original owner and unchanged receiving queue. Whole-queue preflight and FIFO reservations remain unchanged. Logical IDs are never reused or moved.

Committed Spawn adds one live leaf; committed Despawn removes one. RemoveMain leaves the entity occupied. Extraction for a callback does not change membership. Reservations and rejected/failed commands do not enter the tree. Rollback must restore occupancy only where actual inverse lifecycle operations demand it, without allocator rewind or deletion of earlier commits. Marks, pending commands, inverse journal, Ping retention and registered readers are untouched.

Growth doubles all aligned trees by attaching old left owners and fresh empty right owners, including a zero-count occupancy subtree. Existing logical offsets never change. Failed placement returns the original store and rejected owned bundle. The current finite domain 1..131072 remains explicit. Tombstones retain empty physical slots; the count tree skips ranges with no live entities but does not compact, reuse IDs or promise bounded memory under unlimited churn. Root live count must equal physical live metadata count; this is a checked diagnostic obligation, not an approved law.

## Discriminating finite counterexamples required before extension

| Control | Intended observable failure |
| --- | --- |
| Right-before-left traversal | Ascending query order differs after holes and out-of-order commands |
| Skip a nonempty cached-zero subtree | Missing first/middle/last live IDs despite unchanged point lookup |
| Treat RemoveMain as Despawn | Optional/entity membership, stale classification and reinsertion differ |
| Include reservation before barrier | Queries expose pending IDs and failed reservation owners |
| Grow with reversed old/new branches | IDs 1, capacity, capacity+1 and E11 >65536 alias or lose complete owners |
| Restore Main into Aux/wrong leaf/drop fourth cell | Full Main/Aux payload oracle differs; unrelated owners are checked |
| Forget occupancy rollback | Retry, earlier commit and failed publication trace differ |
| Accept foreign/zero/tombstone ID | MissingEntity/unchanged queue gate fails |
| Leak or duplicate zipper/Type owner | Intended undeclared-access, cross-schema, write-through-read, reconstruction and affine duplication controls reject |

Both Motion/Health schemas and explicit-owner/regenerated capture styles must repeat complete main E0–E10, actual E11, access, ownership, FIFO and lifecycle/reader/effect oracles. Compiling semantic mutants must produce the named field counterexample; timeout/checker/build failure is not a kill. General destructive Type recovery, root authority, parallel compute and universal refinement stay open. Follow-up implementation should first check expressibility under checker5s, then compare finite query visitation counts on dense/live, mostly-dead high-water and clustered/dispersed holes. Only separately measured connected workloads can attribute performance benefit. Independent review must explicitly accept the recursive ownership and occupancy mutation boundary before code is written.

## Revision after independent architecture review

Bend datatype constructors and helpers are public. “Private” above means state retained inside the **trusted adapter**, not a module-privacy guarantee. R-A/R-C1 confinement comes from each closed callback being checked at arbitrary affine P/U types, then the trusted adapter choosing the concrete owners. Detached public construction cannot produce the callback's abstract P/U owner. Preserve actual `query.bend:read_main` signature, including `(P -> Tok -> P & V)`, `(U -> U & Maybe<&2,AV>)`, handle and flag arguments and return `P & (U & O)`. Do not replace this with an invented reusable captured closure.

The structural prototype uses actual Base `Array<T> = ALeaf{T} | ANode{Array<T>,Array<T>}`. There is no Vector or unsafe fork/join. Simultaneous `match depth main aux occupied` handles aligned leaves/nodes; owned siblings are retained in the recursion's affine reconstruction context. Its exact result is `ProbeResult<M,A>{main:Array<Maybe<M>>, aux:Array<Maybe<A>>, values:List<&2,U32>, valid:Bool}`. The prototype implements recursive reconstruction; no iterative Frame/zipper claim is made.

The helper DAG is getters → abstract main/aux adapters → client-return helpers → leaf-return/leaf → count/consistent → join/offset → walk/shape → guarded/shaped/check → observation. `walk` self-recurses only on `rest` from `1n++rest`. Templates `~mg/~ag/~use` are closed specialization witnesses, regenerated as in the existing query seam; no affine runtime closure is copied or marked Data. The finite prototype instantiates that provider shape with Tok=Unit, V=U32, AV=U32, O=U32 and a fixture schema: `@-P:Type -> @-U:Type -> (P -> Unit -> P & U32) -> (U -> U & Maybe<&2,U32>) -> Handle<Schema> -> Maybe<&2,U32> -> P -> U -> P & (U & U32)`. The adapter supplies the actual logical handle and flag slot, and regenerates the closed witness on each leaf as the existing query adapter does. Full schema/capture/field integration remains a separate finite runtime gate; the structural probe does not claim those complete observations. No Data.map touches payloads.

Depth is a runtime Nat and is not encoded in Base.Array's type. On an encountered mismatched leaf/node the prototype returns the original owners and `valid=False`. Empty aligned leaves return their original owners with no observation. An empty internal occupancy subtree returns its complete sibling trees unchanged. Cached occupancy consistency is independently recomputed at every occupancy node before skipping. This validates every cached count against child membership, not against component owner presence: live entities may have no Main. An owner-preserving `shape` preflight now descends all Main/Aux/occupancy trees, checks leaf/node alignment against runtime depth, and returns the reconstructed originals with False on any mismatch, including hidden malformed empty subtrees. Its finite negative control deliberately places leaves where depth1 nodes are required beneath a root occupancy count0. The traversal rejects it before the zero-count shortcut; no owner disappears. Both `shape` and `consistent` scan the full structural diagnostic domain: these checks are expressibility/validation evidence and **not a claimed optimized query path**. Before implementation, choose explicitly between paying this preflight in the production subject or deriving shape/count preservation from every trusted writer with adversarial constructor controls outside the interval. Public constructors are not a confinement mechanism; provenance applies only to the original owner held behind the rank-2 boundary. No performance claim is made about either choice.

Membership writers are exactly successful committed `rows_place` and live `rows_remove`. `rows_extract`/restore, Main remove/reinsert, reservation allocation, staging, and returned read owners never change membership. The candidate must update every ancestor count, not only the root. Existing inverse journal restoration changes Main scalar setters; it does not introduce lifecycle inverse semantics. Membership changes during rollback may occur only through existing actually invoked placement/removal paths: tie tests to the real transaction implementation instead of inventing an allocator rewind or new Spawn/Despawn restoration rule.

The earlier Required-only wording is corrected: actual `read_selected` skips `Main=None` for **every** Selection. Optional concerns the optional Aux provider; Flag Present/Absent selection is evaluated separately. Main-absent live IDs remain in occupancy, contribute to every subtree's live count, and become query-visible again when Main is inserted. Distinguish this from Despawn.

The [finite expressibility prototype](../../experiments/s-prep/method/expressibility.bend) exercises depth0/depth2, distinct Type Main/Aux, dead subtree, live Main-absent slot, returned owners reread, balanced structural growth, encountered and hidden-empty shape mismatches and explicit zero/foreign/out-of-capacity guard controls. It is an ownership/structural feasibility slice, not candidate storage code, full query integration, a proof, mutation coverage of all future writers or performance acceptance. Reversed-order/wrong-leaf/stale-count/early-membership mutants and intended abstract-owner duplication/raw-access/reconstruction negatives are independently executed by its runner. Actual reservation/barrier semantics are not implemented by this slice; its early-membership mutant protects the structural prerequisite only.
