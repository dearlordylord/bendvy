# Canonical lifetime-scope execution

A lifetime scope is namespace/name metadata. Its canonical resource owns the actual namespace and the existing full-generation `Scope.Member` list. `ProtectedLifetimeScope` denies ordinary Basic and General resource writers. The gameplay projection contains reusable membership data, never its affine owner.

The command declaration obtains `ScopeGrant` after `RelationGrant`. The same accepted Compilation retains the actual payload/view/policy evidence, deferred descriptions, graph observer and closed resource dispatcher. Its existing Buffer stores `LifetimeScope` beside component, spawn, despawn and relation entries. No second authored queue or transaction runtime is introduced.

Assign checks the actual World/store/token/handle namespaces and allocator liveness. Cleanup first checks its retained World context, coverage of every actual protected graph route by that same catalogue, and every graph-store namespace. It observes membership when the command applies. Its shared `relation-cleanup-control` and `relation-cleanup-engine` execute the existing linked-descendant postorder. Ordinary incoming relations are unlinked; hierarchy children are visited before the parent. The canonical component-removal/despawn implementation returns every actual removed owner. Membership is forgotten only after its actual `Despawned` receipt.

Every outer scope receipt retains the original operation, nested publication receipts and any paused frames. Refusal preserves the original operation and actual incoming owners. Read-only membership observation and refusals preserve the resource cache and stamp. Successful assignment or membership removal refreshes the cache and records the actual publication tick. Scope metadata does not establish liveness.

The engine still performs the initial one-unit drive. Its previous remaining inventory allowance is exactly `remainingOwners * (E + N + 1) * (3 + 2*D + 2*E)` arbitrary Nat units. Complete and zero-remaining cases return before counting or multiplication. The same driver consumes those units in the same frame order; no U32 product, cap or increased allowance is used. The arithmetic is now eager for an incomplete nonzero allowance, which can cost work for very large inventories. This representation repair removes template staging depth; it is not a new cleanup policy or a proved equivalence.

Bend's namespace/name token, separate membership resource and affine recovery receipts are its own ownership contract.

`examples/parallel-lifetime-scopes/scene.bend` executes actual Factory/Schema creation, three actual allocated entities and one ordinary scheduled command actor. It inserts affine component owners 11/22/33, reparents the child, refuses a cycle, assigns the replacement parent to a scope and cleans it twice. The observed result removes owners 11 and 33 into actual receipts, retains the unscoped owner/cache 22, clears graph/inverse/scope caches, retains resource 401 and Local 601 through a handled body error, and leaves no pending entries. This finite execution is not a formal proof.
