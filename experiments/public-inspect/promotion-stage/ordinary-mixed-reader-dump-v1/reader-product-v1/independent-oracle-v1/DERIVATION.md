# Source derivation

The model is based on the producer's immutable source map in SOURCE-BASIS.json (producer commit 76006511eded2711f7a5b98f0d714793c0817f40, main.bend 44a1d0028fc142c7b5dad9f94145ccfd75e0f34ccf5a46d16c71602965dbb826). The self-test hashes the source map and all 87 listed Bend modules. It does not open runtime output, generated artifacts, or receipts.

The setup path in the pinned fixture calls W.create with Factory{1}, reserves and activates entity (namespace 1, id 1), and seeds the component column by Col.swap at the one-based handle id (column index 0). That leaves live flags [false, true], a two-slot world live tree, and the one-slot component column L(some(42)); component lifecycle stamps remain empty. The fixture publishes three initial notices, in source order: Value{11}, the selected removal for entity 1's value component, and the Parent self-relation failure. It then starts empty typed/relation streams around that World.

The consumer enqueues one World command publishing Value{999}, defines one provider named public-dump-reader, and attaches the actual provider through RF.attach. No provider run, prepare, or World barrier occurs in this main. Initialization therefore allocates message reader IDs 1 and 2, a removal owner at registry id 1, and relation reader id 1; the message stream nextReader is 3 and the relation-failure nextReader is 2, with positions still empty. Registration allocates world system id 1, advances nextSystemId to 2, and gives the provider cursor 0. The queued command remains pending, so World events stay at the three initial notices and pending count is 1.

The declared access/use lists are derived in D.all_parameter order: query With(value), event Read(values), event Read(values), removal Read(value), and relation Read(Parent). The removal declaration's access contributes both removal and value. The physical world/context/provider serializer is the unchanged named-app reader-provider-debug observer pinned in the source inventory.

The public dump path enumerates the one live handle and reads the component through its binding presenter, yielding row({"namespace":1,"id":1},[value("value","42")]). The all, repeated, and selected limit-one filters produce that row; zero limit retains alive count 1 but has no rows; disabled debug returns none; reenabled produces the row again. Each dump returns the same app, so physical metadata is unchanged across all seven records. This is a bounded source-derived expectation for this fixture only.

The concatenated pure String has seven records, each with its own trailing LF; the final pure byte string is 10,997 bytes with SHA-256 `82d8408278a971c3f79f24c27e47683e190537ea6e556022b2e23b0b48b93d30`. This byte string remains unchanged in the historical `expected.stdout`. The frozen entry's `main` passes that String to `IO.print`. The pinned `Base.bend` declares `IO.print` through the `print.c` and `print.js` effects; the exact resources are separately source-pinned in `SOURCE-BASIS.json`. The JavaScript effect writes `text + "\n"`, and the C effect writes the supplied text followed by one LF. Therefore raw CLI stdout is the pure String plus one LF: 10,998 bytes, SHA-256 `4636807de53697262e8058e9994264f86552719650270738af4a023403aa0a35`, ending with two LFs. The successor stores deterministic gzip bytes in `expected.stdout.gz` (634 bytes, SHA-256 `2792d05441074bc5888f097a1543d595665929c52a6fc8740c9d8788c26b8232`); its self-test verifies the gzip hash, deterministic recompression, and decompressed bytes. No runtime output is read.
