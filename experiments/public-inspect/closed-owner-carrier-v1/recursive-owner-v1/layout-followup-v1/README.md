# Layout follow-up (source-backed; no new execution)

The retained profile contains 3,037 `lay_eq` leaf samples among 15,056 samples. Dominant parent paths include `val_to → val_arms → val_unbox` (347 samples in one stack), and `val_to → val_box` (277 in one stack); paths also include direct `emit_body`/`emit_fuse`. Counts are unweighted and truncated at nine parents. They identify repeated conversion/comparison activity, not a specific source declaration or installed-compiler cause.

Pinned reference `comp.ts` implements `lay_eq` as identity or two `JSON.stringify` calls (line 992). `val_to` invokes it before BOX/unbox/arm conversion (1644–1647); `val_arms` recursively converts fields. `lay_of` already maps the experimental recursive owner carriers to BOX (938–953), but `lay_node` computes open constructor layouts (980–989): boxing the owner type does not eliminate constructor field conversion. Existing two carriers wrap the exact Frame, then immediately unwrap inside selection/world callbacks. A further owner-only wrapper therefore has no evidenced route to eliminate these comparisons. The captured profile contains no layout objects, widths, argument values or Bend definition provenance; layout sizes cannot honestly be reconstructed from it.

No smaller Bend-source change is justified from these samples alone. Altering Frame/DTO layouts globally would be a broad representation experiment, while replacing the complete 23-grant consumer with narrower entry points would change this experiment's topology without locating the work. Existing full consuming source5 success remains the valid source evidence; no additional checker/backend run was performed.

The smallest compiler-side candidate to investigate separately is an allocation-free comparator preserving the exact existing JSON structural equality, including arm-key iteration order and field order. This is a proposal, not an adopted tool change. A simple recursive comparator is unsafe until the actual Lay graph domain is pinned: sharing, cycles, undefined values, property order, and deep recursion must preserve existing equality/exception behavior. Caching JSON strings in a WeakMap is additionally unsafe while layouts mutate: `lay_node` appends padding to `ks`; no immutability contract has been established.
