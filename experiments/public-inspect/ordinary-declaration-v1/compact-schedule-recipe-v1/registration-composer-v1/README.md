# Registration composer experiment

Unqualified successor to the immutable two-owner foundations. The ordinary
consumer registers read+Added Position, Write Counter, then Without Position;
it snapshots complete empty/two-entity worlds twice enabled and once disabled.
Canonical presented component factories and the resource declaration drive the
operational registrations, observation and generated metadata. No user metadata
adapter is supplied. Operational bodies are registered but not executed here.

`Registered` currently retains an erased metadata fold index. This representation
is not accepted: source05 reaches the 32768-byte closed specialization-key limit
at `Resource.register`; moving concrete rejection continuations to runtime shifts
source07 to `after_resource` when the second owner is accumulated. Source06's
runtime polymorphic success continuation instead refuses specialization on open
erased binders. These are concrete compiler refusals, not deadlines or evidence
that the requested capability is impossible.

Source01–04 preserve distinct formatter/name/signature repairs. All seven actual
stock-five-second attempts, complete source snapshots and unchanged post guards
are retained in `checks/failures-v1/manifest.json` with lossless CAS members.
No runtime output or performance qualification exists for this successor.

exact actual cursors after success, skip, error and rejection and account for
disabled overhead. No mirrored metadata policy is adopted by this experiment.
