## Authority and concrete boundary

Rust Bevy first: pinned ad678262ce53b5d142fe49ee5e08caff6f00ab60 implements `Res<T>` and `ResMut<T>` with one registered ComponentId per resource T, read/write access checked against that ID, and missing-resource validation before access. A grant for resource T does not confer access to a different registered resource U. Fields within the same resource T are a separate matter; this gap concerns distinct resource declarations that Bend stores as fields of one physical aggregate, not arbitrary field privacy inside an application resource. [SystemParam source](https://github.com/bevyengine/bevy/blob/ad678262ce53b5d142fe49ee5e08caff6f00ab60/crates/bevy_ecs/src/system/system_param.rs#L867).

The raw setup-supplied `project:R -> R & V` can nevertheless return a changed R; its type alone does not enforce noninterference. Trusted projection/lens construction and finite normal observations must remain distinct from universal read-only safety. But set accepts the entire R. If R is a product of distinct resources, naming one key does not narrow that replacement to one field. This is a source-level scope mismatch to investigate, not a runtime counterexample already executed.
