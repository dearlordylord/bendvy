Prepared only; independent changed-experiment review required before execution. Reuse the original qualified canonical leaf normal C emitter (33 unchanged source files; original actual normal Native session83618 complete1807-byte oracle PASS). Run only its emitter, not Clang or the native executable. This diagnostic does not replace COMPLETE23 or #54/#56 acceptance.

[Official standalone executable documentation](https://bun.sh/docs/bundler/executables#runtime-arguments-via-bun_options) documents BUN_OPTIONS runtime flags, including CPU profiling, without rebuilding a standalone executable. [Official CPU profiling documentation](https://bun.sh/docs/project/benchmarking#cpu-profiling) documents CPU profiles and named output directories/files. Those current docs are not proof of support in the exact embedded Bun version. The actual stock ELF contains BUN_OPTIONS and CPU-profiler option strings, but the packaged runtime revision is not established. This planned probe qualifies capability on those exact selected bytes, not a replacement Bun executable.

The only compiler environment addition is BUN_OPTIONS specifying --cpu-prof, --cpu-prof-dir and --cpu-prof-name. Compiler argv preserves the original CPU5, stock2.0.35, unchanged entry and -o .c route; the output path is a fresh owned scenario.c. No wrapper interprets compiler JavaScript, patched CLI/compiler, new package or dependency. Existing full resource manifests and exact source/tool/helper pins are retained. No Node profiling, heap capture or allocation sampling is requested. Bun heap-prof is an exit heap snapshot, not allocation sampling.

Admitted execution would invoke the pinned Python collect.py with the exact plan SHA. It checks its interpreter and all input pins, an absent receipt and empty regular profiles directory, then calls the existing unchanged development-v2.py collector. That collector owns the child, heavy lock, raw streams and progressive pre/acquired/post/final guards. Sequence: actual stock C emit30 → profile-validator5 only after successful emit. The validator requires regular nonempty C and the requested valid JSON CPU profile, nonempty samples, consistent node IDs/children, finite timings and sample deltas; its captured stdout retains C/profile digests and all call frames. Emit stdout must match the old empty stdout. Profiler stderr is captured verbatim with digest and byte count; it is diagnostic evidence, not consumer stderr acceptance. The validator does not mutate profile or C. Profile acceptance is distinct from useful compiler phase attribution; frames may be uninformative or minified.

collect.py's finally records every profile-directory artifact, including malformed/partial/unexpected files, even if emit or validation fails. All files remain at their original paths and original collector receipt/raw/guards remain authoritative; a missing profile remains refusal, never rewritten to PASS. No automatic retry, flag adaptation or same-subject rerun. Archive actual raw artifacts only after terminal execution, using existing archive conventions.

The bounded task runner stops then SIGKILLs owned descendants on timeout (`scripts/task_runner.py:kill_descendants`). Runtime help says CPU profiles are written on exit. Neither docs nor embedded option strings establish pre-deadline continuous flushing or hard-kill survival. Consequently full47 emit30 profiling is HELD_UNATTEMPTED regardless of this normal-exit acceptance. No speculative shortened full47 timeout or new busy toy is authorized. Before proposing a termination control, research the actual runtime's flush trigger/periodic write/signal support; freeze a concrete changed control for review if a mechanism exists. Normal exit alone cannot validate the wanted deadline evidence. Full47 subject/oracle and prior failed receipts remain unchanged.

Source-only preparation checks: all33 original source hashes match; two Python files parse as AST. No compiler, profiler, heavy child, backend or probe has run. Execute only after one independent exact-plan launch PASS; preserve the original child handle and terminal receipt.
