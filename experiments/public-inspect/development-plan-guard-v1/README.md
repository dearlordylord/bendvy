# Development command and artifact guard

Mechanical guard for cloned development plans whose top-level entrypoint/artifact fields were corrected while actual command arrays still referenced historical input or output. Independent review caught this before launch; this candidate makes that join deterministic.

`plan_guard.validate(plan, output_dir=plan_path.parent)` belongs before helper import or any command/guard publication in the existing development runner. It reads source/path metadata and returns fixed output paths; it executes no commands and mutates neither the plan nor files. Existing digest/import/resource guards remain authoritative. The detached-v2 collector pins this validator during preparation and loads its captured, hash-verified source during execution, before task-runner imports and artifact dereferences. Historical runtime plans retain their archived collector bytes; this change governs new plans.

The command shapes come from canonical-adoption-v1/detached-v2/development.py and opaque-registry runtime-v1/prepared-attempt03 JS/Native plans. Exact taskset prefix, pinned tool, emit input/output, Node consumer, Clang build input/output, and native consumer joins are checked. Extra flags/stages and mixed affinity prefixes are refused. Caps, environment, oracle, and source completeness remain existing collector responsibilities.

Runtime03 stage is the output directory; legacy development stage names its source directory. The output_dir argument is mandatory. Runner integration passes its actual plan_path.parent explicitly so a poisoned stage plus poisoned commands cannot redirect the whole cohort together. JS also requires the concrete unused scenario.native string: detached-v2 constructs Path(native) before guards. The runtime03 null value is rejected, reproducing its bootstrap failure. Fixed raw, guard, receipt and generated paths must start absent and cannot alias pinned inputs. All paths are absolute lexical canonical and contain no symlink components.

The tempfile controls exercise complete JS/Native positive plans, historical emit entry/output despite a valid old pin, historical consumer/build artifacts, coordinated output poisoning, inventory/closure/pin/actual-entry bytes, every fixed output's freshness, frozen-input overlap, lexical aliases, dangling/ancestor symlinks, command shape/order, and explicit legacy output-directory binding. No compiler/backend/child fixture is launched. Frozen historical plans and their captured collector bytes are unchanged. The current detached-v2 collector now enforces the validator; shared scripts and ECS core are outside this change.

Scope is exclusively canonical-adoption-v1/detached-v2/development.py, including that helper's original prepare shape and its focused runtime plans. Leaf-lift development uses a different relative inventory and is unsupported. Required initial/first-child fields are checked against actual selected helper dereferences; complete hash/resource verification stays with existing guards.

Two exact historical detached-v2 prepare plan bytes are retained as gzip fixtures with original SHA256/path joins in SOURCE-BASIS.json. Positive JS/Native test cases load those fixtures, replace only input/tool/output boundaries with tempfile paths, and preserve command flags/order/caps. This isolates schema checks from old mutable source contents; it does not transfer historical backend qualification. The final 21 controls include null-JS-native reproduction and every pre-child dereferenced field's required presence/type, with all outputs fresh. Existing complete source/resource/tool hash guards remain required.

Root adoption also passes four no-child integration controls against the actual collector: valid plans reach the task-runner import sentinel, stale commands and null Native paths stop before it, and removing the single enforcement call makes the poisoned plan reach that sentinel. The existing 21 validator controls remain separate.
