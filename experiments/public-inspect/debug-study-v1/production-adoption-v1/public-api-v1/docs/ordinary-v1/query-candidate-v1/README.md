## Persistence-independent query constructors

The unprefixed seven constructors accept arbitrary Type payload Column lenses;
none requires a save function, Raw codec, Leaf.Component or Constructed recipe.
Plain and Transient declarations therefore use the same query modes and matchers.
`constructed_*` convenience constructors retain the existing recipe-aware Family
bridge where the store has persistence-capable leaves. Their previous application
continues to source-check; historical v1 diagnostics remain unchanged.

`plain-transient-application.bend` consumes required reads and writes on an actual
plain Column store and actual Leaf.TransientComponent respectively. It specializes
all seven modes for each storage category. Payload contains affine Array<U32>;
its owner-preserving value view returns U32 without a serialization codec.
The generic Plain read-as-write negative is separate from the retained Constructed
negative. Raw v2 controls and source digests are retained in source-checks-v2.

These fixtures author trusted storage lenses as existing Core Family requires;
they do not author a duplicate debug descriptor or access inventory. The ordinary
product-schema owner must eventually derive these lenses for its safe public
facade. Root owns that shared promotion; this candidate does not alter it.


## Registered System and retained App bridge (source-only v3)

`system.bend` accepts any typed capability product Ops(H) and a closed polymorphic
body. It lowers the same query declaration to actual Compose.Plan, derives
registration access from its clauses and retains the ordinary query slot once.
No captured affine environment or #50/#53 ownership policy is selected.

Execution observes the actual affine Registry cursor, calls actual each_since,
and uses existing run_tracked: successful outcomes advance to the committed world
clock; failure/refusal preserve the registry as existing Sys semantics specify.
The result keeps complete output/error/world/registry and slot clauses. The
schedule_dispatch transport distinguishes a reached outcome from registration
refusal and preserves rejected args. It does not pretend refusal ran a body.

`app.bend` grows heterogeneous registered-owner products without fixed arity.
Catalog and structural entries derive from actual Registry IDs/names and the same
slot/clauses; build rejects mixed runtime namespaces preserving owners. Existing
SP.build/Sch retain the real plan, phase/barrier positions and owners. Disabled
describe returns None without constructing Description; Enabled observes the
actual retained schedule. App.run delegates to existing SP.run with its closed
ordinary dispatch/condition/provision hooks, retaining debug and structural data.

`registered-application.bend` specializes real definition, execution and schedule
construction for Plain, Transient and Constructed stores. `nonempty.bend` creates,
reserves, activates and inserts an arbitrary affine Array payload using real ECS
operations, preserving factory and rejected/previous owners. `consumer.bend`
connects those populated worlds to actual registered execution and retained App
construction; Constructed uses its existing nonempty setup. Both direct execution
and App preparation are source-consuming routes. No runtime result is asserted.

Remaining precise integration seam: per-system RegistrationRejected is returned
as a distinct typed schedule_dispatch result. Existing Sch dispatch demands a
Sys.Outcome; this candidate does not select a body-error mapping for a refusal.
Root must review the exact refusal transport before implementing/admitting the
complete generated dispatch route. SP.run's existing condition-false behavior
remains available; this packet does not claim a reached skip/refusal trace.

Before any backend: independently author whole-world/owner/cursor/result/debug
oracles, including multi-family composed write/optional/filters, body failure,

and qualify mutants, guards, JS/Native and unchanged performance gates. v3 source
