# Ordinary instance factory binding

The candidate system-instance module now supplies register, run_tracked, and dispose. A schema specializes its closed runner/create/validate/remove templates once; the actual application retains the returned indexed Instance across operations. It never supplies cleanup metadata callbacks per disposal. Registration invokes existing Sys.register once. Registration failure returns the world without constructing ports. Success obtains actual world namespace and registry id and passes the actual world through create, retaining its returned world and affine ports.

The existing canonical reader fixture is lazy: readers.bend registered_identity constructs Flow/Level Reader owners from the successful registry identity, while prepare_inputs activates both world stream positions on first actual runner invocation. Bind create to that exact reader construction with unchanged world; do not introduce eager position activation at registration. The existing runner, not phantom indices, creates retained stream positions. Schema remove destructures the actual two Reader owners and calls existing caller-core.dispose_streams, which rewrites Flow/Level stream positions while retaining both batches and every other world field.

A concrete factory specialization must preserve this lifecycle and retain registry plus ports through its ordinary execution result. Current system-instance.run_tracked delegates Sys.run_tracked; existing reader fixture uses Sys.run with its own cursor observation, so do not substitute tracked execution into the full fixture implicitly. The concrete reader factory should expose its existing invoke/skip operations over the indexed owner and reassemble its returned registry and ports, retaining the existing independent complete observations. This is the next source patch, not evidence already obtained.
