This is an execution plan, not a passing receipt. The new registered-hook and
retained-reader application has not been checked or executed. The earlier

## Selected complete application

`full.bend` invokes all 24 frozen reference frames through the actual schedule
runner for each of two nominal schemas. It retains registered user bodies,
registered enter hooks, independent reader registrations and their affine reader
owners across frames. Component/resource Arrays and captured command payloads
remain actual owners. Every checkpoint observes the entire physical Array,
machine slots, stream batches/positions, live handles, allocator, clocks,
registration catalogs, external fixture logs and current action metadata.

The reference must execute again and equal `expected.json` structurally,
including all raw-boundary cases. Bend observations must be compared in full,
not by checksums or selected prefixes. Canonical supplemental Bend fields need
an explicit source-derived model; they must not be described as TS-observed
private state. Opaque queue callbacks cannot be serialized: queue length and
actual barrier effects are observable, while source-bound payload construction
and affine custody are separate evidence.

Registered hooks are provisioned before the first frame in this fixture. TS
uses lazy runtime registration. The selected world/transition behavior can be
compared, but this cohort is not yet an equivalent-registration timing subject.
The schedule's dispatch implements condition evaluation; a false condition does
not invoke a body, but the schedule's own dispatch observation is not claimed
identical to the TS skipped-system trace.

receipts before any full #48 completion claim. Full transition-handler failure

performance qualification, production API acceptance or numerical waiver follows
from this finite gate.
