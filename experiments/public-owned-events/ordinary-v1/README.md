# Ordinary owned events — first consumer

This directory preserves the historical first single-family slice. Full #53
semantic acceptance now passes the [independent final review](FINAL-REVIEW.md),
including canonical family readers and combined query/resource gameplay.
Integration CI and the governing issue report are tracked by the coordinator.

`ordinary-owned-event.domain` derives publisher/reader metadata. Publisher gameplay
receives an opaque owner and declared emit grant. Canonical transaction completion
precedes commit or the owned abort receipt. Registration refusal returns original
arguments and their incoming payloads. This first publisher grant does not expose
component/resource mutation; existing ECS rollback remains unchanged.

The reader uses generic affine requests, detached Data projections and an affine
accumulator returned even on semantic failure. The closed runner transports that
result separately from registration success. Its wrapper restores the exact failed
reader activation/position while preserving the existing runtime tick. Runtime
retention, capacity, lag, successful reader advancement and explicit skip reuse the
unchanged Data event runtime. Internal Nat publication IDs are generated by the log;
there is no permanent seen-key ledger or user-supplied key policy.

The fixture executes two nominal schemas with separate actual WorldIO worlds:
empty-reader activation; FIFO publication; failed reader and retry; aborted
publication and complete returned arrays; capacity retirement and lag; explicit
skip; frame retirement; genuine foreign publication refusal; two drains. Every
checkpoint observes full log payload trees, reader/registration state, affine
arguments and world/runtime metadata. Store and user resource are Unit; pending is
always empty and is observed by count. No pending callback or rollback mutation is
claimed by this first fixture. Caller-owned retired/refused/aborted arrays are fully
rendered before their explicit release. No automatic finalizer is introduced.

Raw log/storage/runtime/frame constructors and schema projection functions are
trusted engine administration. The ordinary body sees only the declared capability;
the type checker does not prove arbitrary projection-provider purity. Internal
missing-payload and transport-failure branches are not claimed as ordinary reachable
behavior. `source-control.bend` is only concrete pure typechecking; executable
qualification uses `main.bend` with the real IO namespace allocator.

At the time of this first slice, independent application execution, reached loss,
authority, composition, TS and #28 applicability and final review were still open.
Those gates are now joined in the final review; this old fixture alone is not
the evidence for full family acceptance.

## Current ordinary API and integration boundary

This directory retains the original single-family transport qualification. Its
`ordinary-owned-event` Domain key is metadata, not an independent same-payload-type
log selector. It must not be used as evidence for family isolation. The final
ordinary family path is:

| Application operation | Canonical module(s) |
| --- | --- |
| Pair log path, publication route and family identity | `ordinary-owned-event-binding` |
| Declare one publisher grant or compose unlike grants | `ordinary-owned-event-family-write`, `ordinary-owned-event-declaration` |
| Run a standalone publisher, including empty worlds | `ordinary-owned-event-family-publisher` |
| Combine publication with normal query/resource grants | `ordinary-owned-event-family-query`, `ordinary-owned-event-family-resource` |
| Pair a family binding with actual stream provision/selection | `ordinary-owned-event-family-reader-binding` |
| Register/run confined readers; inspect, skip, dispose | `ordinary-owned-event-family-reader` |
| Complete family retirement/shutdown | `owned-event-family-catalog` leaf/both, through the ordinary reader adapter |
| Scoped projection followed by normal query/resource gameplay in one transaction | `ordinary-owned-event-family-reader-query` |

The paired constructors derive paths, routes, domains and access metadata. The
application still writes explicit erased type/callback indices and closed aliases
required by Bend; these parameters are not all inferred. It does not author an
access list, stream cursor adapter, rollback inverse or recovery packer. Raw
Binding/Setup/Declaration/Catalog constructors, custom providers, Frames and direct
engine runners remain trusted administration. This is not language-wide privacy.

The lower-level implementation consists of `owned-event-scope`, `owned-event-log`,
`owned-event-key-route`, `owned-event-family-storage`, `owned-event-journal`,
`owned-event-family-reader-runtime`, `owned-event-family-lifecycle`,
`owned-event-family-maintenance` and `owned-event-family-reader-query`.
`owned-event-storage`, `owned-event-runtime`, `ordinary-owned-event-query` and
`ordinary-owned-event-resource` retain the earlier single-family source and its
bounded evidence. Their types/helpers remain dependencies; their old examples do
not establish multi-family authority. None of these additions edits the existing
Data-event, query, transaction, Local or World implementations.

Current family authority controls bind the checked reader source exactly; new
combined-grant controls bind its successor separately. Old control results are not
silently promoted to changed-source checks. Backend acceptance and pending gates
remain recorded with each immutable consumer and its delivery packet. The #28
source-reuse decision belongs to the selected protected workload/tool bindings,
not to a count of new files or these API descriptions.
