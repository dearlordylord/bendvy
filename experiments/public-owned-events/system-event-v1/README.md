`system.bend` retains the existing ordinary `System.Owner` with a canonical event Reader/Registry pair. Registration derives access and clauses from the same ordinary read declaration. `run` transfers the single World/affine log through canonical reader domains and `Ev.run`; `skip` delegates to `Ev.skip`. Body success/failure use existing `Reached`; registration rejection returns the original owner, World, and complete Request separately as `RegistrationRefused`.

`main.bend` is a consuming standard/capacity witness: actual adapter registration, activation, publication, successful/failing/retried readers, inactive/active skip, duplicate publication, canonical frame retirement and foreign-reader refusal. It reuses the existing full observer, retaining all payload/sentinel cells, retirement owners, positions, batches, registrations, reader statuses, completions and refused Request. The controls unpack the returned ordinary owner into its single Reader/Registry owner plus the actual returned slot/clauses, retain all those fields in `C.Host`, and reconstruct that same owner on the next operation. Every snapshot includes complete `fastOwner`/`slowOwner` slot/clauses metadata alongside the existing state observer; this is a fixed-schema adapter witness, not a selected public signature. An unexpected empty successful view list retains World/readers/log with `ok=False`; it does not create a public schedule outcome or prove that shape impossible.

Source checks are retained in `evidence`. No backend has run. Existing observer coverage is World metadata plus complete owned log and reader state; it does not expose raw World live/store/pending. The read body is read-only: body failure preserves log/cursor using canonical semantics, but this witness does not establish component rollback. Final affine owners remain in the final consuming Host; no finalizer or disposal policy is introduced.

## App boundary

Ordinary `App.add` accepts the entity-query runner registry nominal type; this event-stream registry is different. Canonical schedule dispatch returns `Sys.Outcome`, while `System.ScheduleDispatch` intentionally distinguishes registration rejection with returned arguments. A total App bridge must preserve this separate refusal; mapping it to success/failure or discarding arguments would select an unapproved contract. Boolean validation alone does not eliminate that sum branch. This experiment therefore exposes the complete typed transport and does not claim actual App dispatch, a public event API, task #53 closure, tool-closure qualification or performance evidence.
