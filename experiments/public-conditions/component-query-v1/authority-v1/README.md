# Composed query Check authority controls

Five actual public positive entry checks cover a generic affine P:Type family
binding through CQ.read, generated Check construction/query-grant use, CD.both,
and nested binary CD.both with three read leaves. Ten intended static refusals
cover cross-schema CQ reads and CD.both, missing query grant, attempting projected
component values through a presence-only grant, writes through query/resource
read grants, abstract H escaping as World/Frame/Handle, and actual App duplication.

The positive arbitrary-P signature preserves the existing Payload -> Payload & V
projection and requires only detached V:Data. These are canonical operation and
rank-2 authority boundaries, not constructor secrecy or purity of arbitrary
trusted providers. Same Data-shaped detached views do not become writable owners.

CHECKS.json retains exact CPU5/default5 argv, source/raw hashes, expected exits,
intended type/quantity diagnostics and unchanged pre/post SOURCE-PINS joins.
No parser, timeout or foreign-IO refusal counts as an intended authority failure.
Compiler source-context whitespace remains raw under narrow stderr attributes.
