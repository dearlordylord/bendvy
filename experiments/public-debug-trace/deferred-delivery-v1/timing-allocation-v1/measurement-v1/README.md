# Complete ordinary On/Off measurement binding

This is the narrow #57 workload binding to the existing `task_runner.Runner`, immutable `CommandLogs`, failure-safe `ReceiptBoundary`/`GuardBoundary`, heavy lock, host Timer and runtime `profile.mjs`. It introduces no subprocess implementation, profiling option, numerical threshold or benchmark-baseline change. Preparation executes no compiler or backend. Root launches only after the entire changed measurement batch receives independent review.

Preparation requires all four plain enabled/disabled JS/Native complete correctness receipts, each original full stdout and empty stderr, exact source closures/tools/resources, and the independently modeled per-mode report. It pins those artifacts and receipts plus a root-established quiet-context file. The generated plan cannot be admitted before these prerequisites exist. All compilation and consumer commands use CPU 11 and the existing serialized heavy lock. Emit/build/runtime limits remain 30/120/5 seconds. Any failed child, wrong full output, missing profile or guard failure leaves the receipt INCOMPLETE.

The batch compiles the two existing timed entries for JS and Native, then takes the existing contract's two warmups per mode/backend and twenty pairs per backend. Ten pairs run enabled first and ten disabled first; seed 20261007 shuffles their order deterministically. Only these scheduling constants are reused from `benchmarks/contract.json`, not its #28 workload, baseline, alpha, statistical verdict or iterations. Every run compares the entire independent mode report and verifies exact Timer elapsedNs/bytes/FNV-1a32 stderr. Raw streams, full pre/post pins, command outcomes and CPU/load/pressure context remain retained. The summary reports count, median and range per mode/backend, without a speed verdict.

The four additional runs use unchanged `profile.mjs`: enabled CPU, enabled heap, disabled CPU and disabled heap. Each profiles the qualified unchanged plain generated JS and validates its full stdout and one successful IO completion. CPU sampling is 100 microseconds. Heap sampling is 32768 bytes and includes objects collected by major/minor GC, with the existing 20ms drain. Sampling estimates are not RSS, exact physical allocation or unprofiled elapsed time. CPU and heap profiles remain separate reports.

The host timer covers fresh World creation, all 21 steps/31 checkpoints/10 runs, trace delivery/reset/unsubscribe, complete owner observations, report construction and UTF-8 materialization/hash. Output flush occurs after the timer stops. Runtime profiles separately include process/module initialization and IO. Enabled and disabled reports intentionally have different required trace/description bytes; this is complete lifecycle plus rendering overhead, not isolated hook cost, gameplay throughput or a TS/global performance comparison. Source-model semantic parity of World/readers/owners remains independently checked apart from the expected trace collectors/debug DTOs.

`binding.py prepare --output ABSENT_OUTPUT --quiet-context ROOT_CONTEXT` produces the exact reviewable batch plan. After review root may invoke `binding.py execute --plan PLAN --plan-sha256 HASH` with the plan's pinned Python. No execution has occurred in this source-preparation commit. The unchanged admission/guard machinery and the new subject validation/command binding are reviewable separately. Final feature performance targets remain #21/#23/#24; final #57 integration, default #28 and CI remain separate gates.
