# E10 integrated static access boundary

Fresh checker controls target the committed actual integrated subjects at
`1e613f8`: closed `systems` A/B bodies through `audited-invoker`, concrete
`host.motion_read`/`health_read`, and `host.query` supplying fresh opaque read
providers. This is new evidence at these call sites; historical R-A/R-C1 or
standalone token controls do not supply this acceptance.

Run `python3 experiments/s-integrate/integrated-access-run.py`. The compiling
positive threads actual nominal Host/world/service owners into these entry
points for both schemas. Each negative is one temporary-copy mutation of that
same positive closure, with the original positive as its paired control. Shared
modules are unchanged. Evidence pins every imported local subject, compiler
binary, Base and runner, records checker elapsed time and exact diagnostics.
Every invocation has a five-second limit with task-owned process-group cleanup.
No runtime execution or general proof is claimed by this static package.

The successful cases include reversible actual A/B write provisioning and
read-only provider ownership return. The negative controls require their exact
`motion_a`, `motion_read` or `log` diagnostic location; parse/import errors,
TODOs, unrelated failures and timeouts do not count. The mutation source hashes
and complete diagnostics are retained for replay. The first diagnostic harness
attempt expected the source variable spelling `owner`/`aux`; the checker reports
their types `Owner`/`Aux`. Assertions were corrected to those exact actual
boundary diagnostics; no subject or intended rejection was changed.

These results confine the supplied arbitrary abstract owners in these callbacks.
All public concrete constructors remain accessible: applications may construct
detached values, and trusted modules own the concrete representation. This does
not prove universal unforgeable factory/root authority, module privacy or
physical pointer identity. Actual imported bodies and returned Type owners are
checked; no Data-only payload replacement or unsafe authority is introduced.

The destructive negative establishes that this read-only opaque callback cannot
perform the attempted destructive replacement. It does not make an arbitrary
trusted concrete destructive setter recoverable. The integrated setter API
currently exposes numeric slot-zero updates with captured inverse scalars;
general destruction/extraction and recoverable destructive Type mutation need a
separate explicit contract and redesign. Successful structural disposal and
three-backend E10 foreign-command behavior remain separate runtime gates. No
production API/layout, new numerical threshold or dependency is adopted.
