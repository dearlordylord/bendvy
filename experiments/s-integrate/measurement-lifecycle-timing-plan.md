# Exact lifecycle timing seam — inventory before implementation

Earlier lifecycle checkpoints compare all queried/stored fields and current pending/target/foreign lookups. The frozen TS reference additionally performs every historical stale-handle lookup at every boundary. That history is required in this next adapter; earlier records remain bounded checkpoints and are not relabeled as the entire frozen workload.

Use a measurement-owned wrapper around the actual L state, adding only an issued-handle history, an ordered observation checksum and a correctness-output flag. The underlying Host, worlds, affine payloads, registry, clock and command operations stay actual. A registered selector derives first/middle/last from the actual required query, rather than from an oracle map. A registered Observer declares Ledger access and reads required full payload/Aux/Flag fields, the resource, pending/current target/foreign classification and every historical stale handle. Disposal appends the actual selected handle to history. Failed lookups and issued IDs are observed; no handle is reconstructed from an expected numeric sequence.

Match TS/Bend timing schedules explicitly: Select+Reserve, Observe, Deferred, Observe, Dispose+Deferred, Observe,64 times. The selector callback is a named setup alignment, executed on both sides; structural and observer descriptor construction occurs before the clock starts; TS internal lazy registration remains in the first actual invocation. TS/Bend use the same per-boundary query/lookup/resource work. The intentional foreign lookup divergence remains visible and is checked separately, rather than normalized into equivalence. Both factories/worlds are genuinely created, and the foreign fixture is actually published and observed before its owner is discarded.

Only public observer work stays in the timed interval. Redundant diagnostic O.world, JSON rendering and final dumps are excluded; full-field correctness mode still records the actual observer values before any timing sample is accepted. An ordered checksum consumes every observation field inside the interval on both backends, preventing deferred observation work from moving after stop. The final owner and captures are inspected afterward. Runtime/checker5s and failed-field gates remain unchanged. The larger tuple-output failures remain explicit until a fresh complete-field run actually passes; compact hashes alone cannot approve those sizes.

Timing uses one fresh identical warmup world and one fresh measured64-iteration world per child, seven rotated Native/TS/JS repetitions and common clean C launcher child wait4 RSS (the Python-parent inherited peak is explicitly excluded). No numerical threshold is approved, and no unverified sample becomes a speed result. If coarse Bend milliseconds prevent a meaningful ratio, report the resolution limitation before any explicitly repinned batching change.
