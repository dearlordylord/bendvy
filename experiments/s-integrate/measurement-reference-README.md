# Pinned TS integrated measurement reference — correctness checkpoint

```sh
node experiments/s-integrate/measurement-reference.mjs --all
```

Existing Node v24.20.0 directly imports public `bevy-ts` at `3040a3b2a3f28fa8554d856f9ccb6bf5433fa334`. No dependencies are installed. The parent runs thirty fresh child processes, each with a five-second `execFileSync` deadline (default SIGTERM cleanup). Every lane must pass; a failed assertion/child aborts instead of producing a passing sample. Evidence records adapter, measurement-contract, trace and reference-module hashes. Only the adapter's own evidence is regenerated; one compact JSON result per lane keeps the trace reviewable.

## Frozen inputs and actual work

All five workloads run separately for Motion and Health with initial live counts 64, 256 and 1024, width four, and 64 authored iterations. Nominal component/resource descriptors and actual callback/provider instances are created separately for each schema. Motion uses Position/Velocity/Selected/MotionLedger; Health uses Vitals/Armor/Tracked/HealthLedger. All start with an actual Seed system, raw returned reservations and explicit deferred barrier. Main cells are `[j,j+1,j+2,j+3]`, Aux iff `j%3==0`, Flag iff `j%3==1`; complete metadata and Aux values match the contract. Ledger starts `[0,101,102,103]`, epoch4. Sparse alone omits Main unless `j%8==0`.

| Workload | Executed public work and checked observations |
|---|---|
| Dense | Same Update instance dispatches 64 times. Declared Main write reads all four cells, increments cell0 and retains every other field. Each row uses the actual resource provider to increment totals0. Full final ordered rows and Ledger are deep-compared. |
| Sparse | Same writes on required Main membership, plus separate present/absent/optional Aux queries every iteration. Complete Main/Aux/Flag values and raw IDs feed ordered per-selection checksums, checked against independent fixture enumeration. Final full objects are also deep-compared. |
| Lifecycle/churn | Actual reserve, pending lookup/query checkpoint, explicit barrier, then Main removal and despawn of rotating first/middle/last current live row and second barrier. | Readers | Same Fast and Slow instances prime after seed+barrier and before transient publication; public frame/tick registration observations are recorded. Both finally drain. Every callback checks all live fields, added/changed full rows, retained removed/despawn IDs, messages and event lag; public debug `missed` is empty. All 84 callbacks/lane are recorded. |
| Failed transaction | Actual A commits cell0+1, Ledger+1, message A and reservation. Same B reads messages, writes old→old+10→old+30, Ledger+100, reserves and emits, then fails code7. Identical B retry reads the same retained messages and succeeds; another pre-barrier checkpoint verifies payloads and both successful spawns remain pending. One explicit barrier applies A/B commands, full membership is checked, then disposal+barrier restores initial count. All failed escaped IDs remain Missing at every subsequent checkpoint. |

A/B messages encode A(i) as `2*i`, B(i) as `2*i+1`. A's spawned cells are `[i,20,30,40]`, B's `[i,200,300,400]`, retaining schema metadata. B primes once before A's first publication, so its final capture count is129 versus A64. That priming invocation reads no messages and stages no effects. Failed and successful B attempts both retain lexical capture increments and external Audit effects; all192 ordered effects are checked. Each iteration's raw IDs are exactly `n+3*i+1`, failed `n+3*i+2`, retry `n+3*i+3`; normalization cannot hide reissue or rewind. This is the explicit returned capture counter scenario, not general Local/closure policy.

Readers use the pinned public default capacity65536 (`Runtime.streamCapacity`); this workload never reaches capacity, so it tests retained delivery/draining, not overflow acceptance. Messages are whole publication batches; lifecycle records retain their separate semantics. No private cursor/log occupancy is inspected. Final unread positions are inferred from successful full drains; a further empty read is not performed. Public debug frame/tick/outcome/missed observations are actual runtime events, not adapter clock substitution.

## Fresh evidence and limits

**30/30 PASS**, each fresh child within its five-second limit. Complete objects are compared before compact hashes/ranges/samples are recorded. Per-iteration checksums supplement exact final comparisons, never replace them. Lifecycle records keep each removed raw ID (`lastStale`) so the complete stale prefix is reconstructible; all prefix handles were actually checked. Transaction snapshots record every failure/retry/apply/dispose boundary. Assertions and expected fixtures are authored independently of runtime internals, but this remains finite reference execution, not a universal proof or compiling-mutant gate.

During development the first reader expectation incorrectly advanced the priming removal index to−2; actual retained delivery exposed it. The corrected independent cursor starts at−1. Fresh replay above uses the corrected source; no failed sample is counted as passing.

Dense/Sparse single-run durations remain diagnostics only, separating setup, dispatched iterations and final observation/validation. Other lanes deliberately collect no timings. Peak RSS includes Node imports/setup/execution/validation and is not per-component allocation. Source-side maps in the adapter construct/check expected observations and track actual returned IDs; actual workload updates and reads all go through runtime dispatch and declared providers, not direct storage or array mutation.

Before comparative timing, require equivalent Bend/Native/JS operation and observation work and the separate integrated semantic gates; freeze CPU affinity, worker count, timing flags and limits; run fresh-world warmups and seven measured repetitions, retaining dispatch and required barrier costs. Backend alternation, ratios, uncertainty and numerical thresholds are **not** established here. The separate full-trace ownership/access/mutation gates, production layout, allocator policy, larger scaling and performance acceptance remain open. No new law, threshold, dependency or runtime policy is approved by this checkpoint.
