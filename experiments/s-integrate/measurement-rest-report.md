## Lifecycle and reader implementation

`measurement-lifecycle.bend` threads actual Host, registry, reader and clock owners through `D.tick`. A registered reservation callback uses `C.reserve`; an explicit Deferred node publishes it. A required query returns the actual target handle at rotating first/middle/last rank; disposal stages actual remove+despawn and a second Deferred node applies them. Each of the 192 boundaries now invokes actual required `Q.each`, three actual `Q.lookup` operations and an owner-preserving full `O.world` observation. The checker sees abstract payload callbacks and affine array owners. The trusted measurement wrapper holds only the actual Host plus count/iteration and issued Data handles; it does not reconstruct worlds from observations.

`measurement-readers.bend` retains the same registered Fast/Slow instances. The transient is reserved/flushed, updated through a fresh abstract-owner callback into an actual SystemTx, and its iteration message is published through Host. Actual `H.motion_invoke`/`health_invoke` produce the complete reader query, added/changed payloads, lifecycle/message deliveries, boundaries and `ReadDone` diagnostics. Disposal follows reads; both instances drain after the 64th disposal. The validator compares all 84 complete read records, all 84 diagnostics, all 64 returned reservations, final full fields/query, retained capture counts and clocks. It also compares every full normalized query with fresh pinned TS execution.

Setup is explicit: initial rows are reserved by the trusted fixture before dispatch and one actual Deferred tick makes them live. TS performs an additional Seed callback, so every reader callback has Bend tick = TS tick − 1; frame numbers agree. The validator checks that exact offset, not merely payload parity. The same-factory foreign handle is obtained from a second world's real reservation, whose owner is then discarded; TS makes that second-world entity live. Both expose the same approved namespace-mismatch result in Alpha, but foreign-world lifecycle equivalence is not claimed. Intermediate lifecycle observations and final reader observations are trusted provider calls outside a dispatched Observe callback, so those observation calls do not advance the dispatcher clock. Mutation callbacks, reader callbacks and all barriers use the actual dispatcher.

TS creates iteration-specific structural/update callback descriptors; the Bend adapter retains closed descriptors and obtains the iteration from its trusted wrapper. Only Fast/Slow same-instance identity is part of the reader contract. This setup difference must be resolved or excluded consistently before comparative timing; these files currently report correctness, not timing samples.

Both 1024-size schemas/backends and Health256 Native reached the unchanged five-second whole-process limit. `measurement-lifecycle-baseline-evidence.json` retains exact original source hashes, full-world successes and two detected compiling mutants. That older checkpoint did not establish per-boundary public query execution; it remains a baseline, not current acceptance.

The first reader run on the original lifecycle dependency passed Motion/Health64/256 on Native and JS, while all four 1024 runs hit five seconds. Its subsequent no-main-change mutant checker reached five seconds, aborting before a final evidence file was written. This interrupted result is retained here, not counted as a complete mutation gate. During that run the lifecycle source was edited; the old runner copied imports again for each mutant. The current runners freeze every imported source byte at startup and persist each completed case before starting mutants, preventing this provenance defect. CPU affinity was not pinned in either first run. The current replay explicitly sets affinity to CPU10 for the runner and all descendant checker, compiler, Node and native processes; checker/runtime limits remain five seconds.

Neither timeout establishes a storage-only cause: the correctness executable prints full intermediate observations, and the five-second bound includes setup, queries, observation encoding, output transport and final dump. A compact observation diagnostic is a separate follow-up; full-field failures must not disappear behind checksum-only success. Seven-sample steady timing, equivalent TS timing setup, warmups, memory/occupancy measurements and numerical acceptance remain open. The failed-transaction measurement has been assigned separately to the transaction worker; no result for that lane is inferred here.
