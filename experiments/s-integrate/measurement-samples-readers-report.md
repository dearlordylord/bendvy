# CPU5 Readers steady-state samples

Four cases completed seven fresh Native/JS/TS repetitions, with every warmup and sample checked against the fresh authoritative TS reference. Both schemas at1024 failed Native/JS five-second complete-process prerequisites; no ratios are reported for them. Timings are descriptive, not approved performance acceptance.

Command: `python3 experiments/s-integrate/measurement-samples-readers-run.py`. The new Bend wrapper uses the existing actual ReaderState owner, registered Fast/Slow systems, opaque transaction update, dispatcher tick, explicit barriers, lifecycle and Ping logs. It runs the identical64 spawn/barrier → update/Fast/(Slow every fourth iteration) → remove/despawn/barrier iterations. Setup, priming, final drain, final world observation and serialization are outside the measured interval on both sides. One fresh warmup precedes one fresh measured world per process. Original measurement/runtime sources are unchanged.

Each timed Bend drain extracts actual event Data and retains it in a reversed list of64 batches. The returned affine Runtime continues through disposal and the next iteration. After stop IO.now, batches are reversed once and rendered with the unchanged full renderer. Full Main/Aux/Flag values, query/added/changed lists, lifecycle identities, Ping payloads, boundaries and diagnostics are actual emitted observations. Existing Host query/read calls construct the Views and lists before returning; generated JavaScript was inspected to confirm actual tick/runtime_read completes before recursion and IO.now is bound before motion_emit. The manual generated-code ordering inspection is recorded in `measurement-samples-reader-order.json`; source closure hashes are in the sampling evidence. Generated temporary artifacts were removed by the runner. Serialization is deferred; actual callback/query/retention work is not replaced by fixture calculations or numeric loops.

The new TS adapter retains the source's actual queries and `.get`, added/changed queries, removed/despawned `.all`, Ping `.all`/lagged and debug observer calls. It captures their actual ordered values, excludes TS-only structuredClone/SHA/oracle comparisons from the timed interval, and verifies the snapshots afterward. The authored callback replaces component objects rather than mutating retained snapshots. It retains source per-iteration Spawn/Update/Dispose descriptor construction (Bend uses preregistered descriptors); this setup difference remains a comparison limit. The same Fast/Slow instances are retained throughout. Reference clocks remain normalized exactly as in the original validator, Bend tick = TS tick−1 due to seed setup.

Every Bend world passes the unchanged234-line validator:84 complete Read records,84 actual ReadDone diagnostics,64 complete reservation records, the complete final world/query and reader call counts. The new TS comparator independently checks every actual row field/order, added/changed membership, lifecycle/message delivery, lag, diagnostics and final objects. Seven finite comparator perturbations are rejected (Main slot3, Aux slot3, Flag, lifecycle ID, Ping payload, lag and clock); they are comparator controls, not runtime mutations or ECS proofs. `python3 experiments/s-integrate/measurement-samples-validation-controls.py` runs those controls on fresh actual TS output on CPU6, outside timing sampling.

All sampling uses CPU5, the same Node binary for JS/TS, NativeO3 single worker GPUoff, rotated backend order, five-second process groups and checker5s/codegen30s/clang120s. Each sample's raw clock, contaminated wait4 reading, command and source/tool hashes are preserved. **RSS comparisons are withdrawn:** direct `posix_spawn`/`wait4` readings inherit an observer-dependent floor. They cannot be interpreted as backend peak memory. Historical raw values and summaries are retained as explicitly contaminated/withdrawn diagnostics; no corrected ECS memory samples exist. See `measurement-samples-rss-report.md`. Retention added for post-timer validation can still affect GC and process completion. A1024 timeout therefore does not alone locate the cost in the timed body. Failed prerequisites are not retried seven times. Native64 samples below10ms are resolution-limited and cannot support stable acceptance ratios.
