# Storage stage E0/E1: bounded executable evidence

The actual owned storage/factory/commands/query slice passes the recorded
E0/E1, colliding foreign-handle and FIFO-overwrite observations on Native and JS.
This is part of #19, not its completed runtime or dispatcher gate.

## Implemented subjects

- `identity.create` consumes a real Factory owner and assigns a namespace;
  `reserve_id` consumes a local ID independently of command publication. The
  fixture creates Motion alpha/beta then Health alpha/beta through one returned
  Factory lineage: namespaces 1/2/3/4 and final factory counter5. Independent
  public bootstrap roots remain a trusted-premise limitation.
- `storage.World` owns separate nominal Main/Aux/Ledger Type payloads, optional
  Main/Aux/Flag membership, marks and a reverse pending command list. Its
  `with_main`/`with_ledger` invoke an affine trusted transform and return the
  actual owner to storage. Application callbacks receive no extraction authority.
- `commands.reserve`, `insert_main`, `insert_flag`, `remove_main`, `remove_flag`
  and `despawn` own their payload transfer. Foreign wrappers check the actual
  handle namespace before queue mutation and return unqueued payload owners.
  `apply(world,tick)` is explicit, reverses pending commands into FIFO and returns
  ordered lifecycle Change notifications. Same-world stale targets do not revive.
- `query.each` and `query.lookup` supply fresh getters and arbitrary abstract
  Main/Aux providers to a closed callback, reconstructing rows from returned
  owners. Required/present/absent/optional selections check Main and Flag
  independently of Aux. The list adapter maintains ascending logical IDs.

The source contains removal/despawn paths for integration. This stage's runtime
acceptance exercises reserve/apply/insert overwrite, not the complete E6–E9
removal, disposal and retained-log trace; those joined gates remain open.

## Fresh checks

Run `python3 experiments/s-integrate/storage-stage-run.py`. The runner uses the
existing T05 process/build helpers: checker and runtime each <=5 seconds;
C/JS generation <=30 seconds; clang <=120 seconds. Each build is fresh in a
task-owned temporary directory. No dependency is installed. Reference HEADs are
checked against the tracked manifest; compiler and Base identities are recorded.

`storage-stage-evidence.json` records source hashes, reference identity, the seven
negative/control results and compiled mutant outputs. `storage-stage-observed.txt`
contains the complete original Native/JS transcript. It is compared against
full-field structured expectations generated by the independent storage contract
model, not adopted as a golden output from the implementation.

The runner also executes the pinned public TS main trace afresh and compares
eight E0/E1 snapshots: two schemas, alpha/beta, pending/live. It checks full
Q/Q+/Q-/Q? values, Aux-only rows, all Ledger fields and selected lookup outcomes.
It compares the public subset only: Bend raw namespaces, allocator/pending
encodings and mark ticks are adapter diagnostics; they are not asserted as TS
representation parity. The TS foreign collision resolves a local entity and is
recorded separately from the selected Bend MissingEntity divergence.

Both schema runs additionally queue a legitimate full Main payload in each
receiver, reject the other world's actual colliding handle in both directions,
read all fields from each returned rejected Type payload, and re-observe complete
receiver rows/resources/Mode/queue. Finally, accepted writes 77,80,81 to alpha.a
are applied through the actual FIFO barrier and produce full V(81).

The seven negative programs instantiate the actual integrated query provider
alongside the accepted closed reader: write through read, undeclared Aux getter,
wrong nominal token, concrete reconstruction, missing owner, consumed owner and
cross-schema handle. Their intended diagnostics are required; arbitrary failure
or timeout is not accepted. All constructors remain public. These checks concern
the abstract callback boundary, not language-wide unforgeability.

Five independently copied semantic mutants pass checking and compile/run on
Native/JS, then differ from the original at their intended observations: removing
foreign lookup validation, removing foreign command validation, reversing query
output order, reversing command FIFO, and assigning a constant namespace.

## Limits and follow-ups

No system dispatcher, empty-schedule call, transaction failure, lexical capture,
registered reader or retention policy runs in this fixture. Pending values remain
absent across actual read operations until apply; the real no-implicit-tick-flush
gate requires the dispatcher join. E8 lifetime/order and E9 disposal checks remain
required before those capabilities pass. No proof or universal refinement is
inferred from this trace or the earlier signature canaries.

The owned-list adapter scans/rebuilds lists; Main edit extracts and reinserts via
two traversals. Command application and formatting are not optimized for the
public65536 workload. Keep this baseline, join the complete trace, and measure
equivalent integrated workloads before selecting storage or accepting native/JS
performance. Root authority, exhaustion/reuse, arbitrary destructive recovery,
general Local and unrestricted Type payload policy remain their documented
follow-ups. The shared interface and exact trace retain precedence over this
bounded report.
