# Stateful ordinary conditions over captured schedules

Source candidate, backend qualification pending. This extends the frozen first
consumer without changing its source or the existing condition implementation.
`captured-schedule-condition` accepts ordinary `Condition` bindings, keeps their
actual heterogeneous owners, and derives their registered identities from those
bindings. Condition identities are validated separately from executable system
IDs. Complete duplicate/identity/requirement admission precedes all evaluation.
Existing #35 unavailable/rejected-condition errors and observation prefixes are
preserved; successful false evaluation skips the body but retains condition state.

Two nominal schemas combine a query capture containing two Arrays and a resource
capture containing another Array. The resource product contains an actual ordinary
machine State. A registered StateChanged condition gates the query; an independently
composed constant condition gates the resource system. The consumer executes first,
unchanged skip, genuine state insertion/change, entered resource failure, retry and
foreign refusal. Observations retain complete allocated component payloads/stamps,
live tree, World metadata/resource/machine stream/revision, actual capture arrays,
query and condition cursors, condition descriptions, arguments, plans and logs.
Pending commands are absent in this consumer; no queued-owner coverage is claimed.

`SOURCE-CHECK.json` retains the affected scenario PASS and concrete main's foreign
limitation. Parent-provided state/resource helper checks and initial repair logs are
retained separately. No backend output was used to author this source. Ordinary
first-pair and separate admission/lifecycle evidence remain independently frozen;
this leaf does not claim full #51 acceptance or new ownership rules.
