# Automatic recovery App authority and compatibility controls

Four positive entry checks cover actual App registration/run and legacy
Declaration use through the classic recovery registration and automatic bridge.
Eight intended refusals cover cross-schema App invocation, affine App duplication,
undeclared same-payload sibling mutation, write-through-read, missing resource
grant, and abstract gameplay H escaping as World, Frame or Handle. The
`legacy.bend` support file constructs the unchanged two-field Declaration from
the existing canonical empty/access operations; it does not fabricate typed uses.

The legacy automatic positive checks the constructor's accepted input type,
not successful registration: the ordinary bridge detects opaque metadata and
returns the original Before App and incoming capture through AppendRejected.
Executable preservation is separately prepared under opaque-rejection-v1.
Classic recovery remains available for trusted/custom raw Declaration builders.
No raw binding/metadata constructor secrecy or universal provider purity follows.

`CHECKS.json` retains exact CPU5/five-second commands, intended exits, source/raw
hashes and pre/post `SOURCE-PINS.json` joins. Legacy name/kind repair predecessor
sources/diagnostics remain excluded from intended authority-refusal results.
