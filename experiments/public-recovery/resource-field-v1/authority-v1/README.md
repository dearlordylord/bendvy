# New resource-field recovery authority controls

Two positives and eight intended negatives check the actual canonical field
recovery API. `positive-run` consumes the ordinary registered owner/World/Args;
`positive-write` consumes the opaque new declaration grant. `cross-schema-run`
rejects an Other-schema World at that actual registered entry. `undeclared-sibling`
requests the distinct same-payload sibling identity through the Target-only grant.
`wrong-binding-identity` and `wrong-binding-schema` reject mismatched Binding
indices at the actual new `Field.declaration` constructor. These controls do not
claim that raw trusted Binding constructors are secret.

`write-through-read` passes an ordinary selected-field Read grant where generated
recoverable Write is required. `world-escape` and `frame-escape` reject treating
abstract gameplay H as World or the closed journal Frame. `duplicate-owner`
rejects copying the actual registered affine owner/capture. Existing #52 IO callback,
component inverse and other family controls remain within their original source-
bound scope; these fixtures add no generic adversarial-provider purity claim.

`CHECKS.json` joins exact commands, CPU5/five-second cap, raw diagnostics, source
hashes and unchanged pre/post `SOURCE-PINS.json`. All final negatives fail for
intended type or affine reasons, not parser errors/deadlines. Two initial import-
placement parser failures retain complete predecessor sources and raw diagnostics
under `*.parser-predecessor.*`; they are not counted as intended refusals.
No backend, law, proof, new authority contract or cleanup claim is introduced.

The seven exact `.gitattributes` entries preserve compiler-emitted trailing spaces
on blank source-context lines in immutable raw stderr; diagnostics are not edited.
