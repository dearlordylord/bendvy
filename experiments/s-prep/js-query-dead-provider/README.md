## Why the two arguments are removable in this closed program

The client has six identifier parameters and exactly one return statement: `(owner, (aux, handle))`, preserving the entire affine Type owner, aux and handle. Its first two provider parameters are never referenced. The exact first provider forwards only its own bound owner/token parameters to a pinned immutable global read helper; its nested provider is constructed only if called. The second provider forwards only its own bound parameter to the pinned aux read helper. Neither provider captures a runtime owner or other local value.

The pinned `run_clo` runtime allocates a fresh wrapper function, connects it to the fresh provider function through `f.j` and `j.f`, and returns it. In the closed ordinary-function runtime these operations have no observable effect when the result is unused. The original client remains unchanged; the two call arguments become `null` at their original positions. All other arguments retain their exact bytes and evaluation order. No reads, checks, array writes, logical callbacks or workload results are skipped or specialized. The original source/runtime APIs and full Type ownership return remain intact.

This is a bounded emitted-code causal probe. It does not approve a universal compiler rule, source refinement, Data-only raw values, a new law/proof, dependency, compiler/kernel edit, Native optimization, canonical reset or adoption.

## Fail-closed guards and controls

The recipe admits only explicit input hashes with all 29 actual source hashes. Exact client/caller/read-helper names and expected site membership are pinned. They must resolve to unique immutable global functions with no shadows. The client body and complete owner/aux/handle return must match exactly, both provider parameters must remain unused, and each provider arrow must match the closed forwarding shape. Changed `run_clo`, captured values, unknown callees, client exposure/reflection, arguments/eval, accessors, proxies or prototype access refuse the program. Original client/callback definitions and all other call arguments remain untouched.

The retained witness preserves an entire Type owner with main array and ledger, four cells and metadata, retained immutable Data view, full aux and nominal handle. It observes identical remaining-argument order and a remaining argument exception; the providers and their read helpers must never execute. Sixteen refusal controls cover used get/ag parameters, captured owner, impure provider body, changed runtime, unknown client, FFI/identity observation, proxy/prototype/getter, shadowed runtime/client, function/arguments reflection and a changed owner return.
