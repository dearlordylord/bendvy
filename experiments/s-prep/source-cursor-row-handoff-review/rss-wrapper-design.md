# Fresh-child RSS observer design

Permit a separate v8 raw observer/wrapper probe. A fresh Python wrapper per workload may start exactly one subprocess, wait/communicate through the unchanged bounded supervisor, and then record Linux `resource.getrusage(RUSAGE_CHILDREN).ru_maxrss` in KiB. Fresh wrapper process scope avoids contamination from prior role children. Keep exact Node/program or Native threads1/gpuoff arguments, minimal environment, parent5-second cap, pinned Python/wrapper/supervisor/program bytes and pre/post checks. No child may survive; nonzero exit, timeout, missing/truncated/invalid sidecar must fail the role rather than provide a passing RSS observation.

The quantity is the peak resident set of the child process; if descendants occur, Linux reports the maximum individual child's peak rather than simultaneous aggregate process-tree memory. Therefore call it child peakRSS, not aggregate tree memory. It includes setup, warmup, complete workload and observation, not active transaction memory. Native threads share the same process memory. Record output/exit/argv/environment and RSS provenance together, preserving original full65 field validation. Any wrapper-side parsing must not alter original stdout or measure authored elapsed itself; authored bracket values remain separate.

Wrapper creation/measurement overhead lies outside authored elapsed brackets but can perturb scheduling. This is descriptive raw diagnostics only, not qualification, canonical performance acceptance or adoption. No execution occurred for this design review; immutable v7 observer stays unchanged.
