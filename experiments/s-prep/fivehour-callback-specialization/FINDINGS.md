# Unchanged opaque callback specialization boundary

The present wrappers can specialize trusted provider implementations, but this investigation does not find a source-only way to remove the original opaque callback's ordinary function arguments while preserving its definition/header. The actual combined static Held output still calls original health_body with four fresh curried run_clo chains (generated /tmp/bendvy-fivehour-static-combined-js.js:5724). Its callback consumes get/set/ledger/setledger as ordinary runtime arguments; frozen Owner erasure does not freeze those arguments. The earlier frozen partial-application experiment retained those same constructions.

Installed guide says a leading ~ argument is substituted as syntax into a separately compiled instance; it must be closed. A small affine Box canary freezes both the unchanged opaque client and concrete read/write providers in an outer template. Source checker5s/codegen30s pass, yet emitted invoke still constructs read/write curried closures and calls the original callback. evidence.json pins the complete generated invoke and tool/source hashes. This finite negative lowering observation is not a theorem about every possible source transformation or a timing/allocation-dominance claim.

Read-only reference compiler supports the explanation: bend.ts:134–139 defines closed template instances; comp.ts:2981–2992 emits live Lam/Mat function values as run_clo closures. Reference source and installed compiler are pinned separately; source correspondence is explanatory, while installed output is the actual observation. Base Array lowering and trusted static provider helpers cannot change how an unchanged ordinary callback receives function values.

A callback template with ~get/~set/~ledger/~setledger could expose direct calls, but that requires a cloned/retyped callback or new callback ABI. It would need explicit scope and callback-equivalence controls, undeclared-access/read-write/affine negatives, exact effects/journal/rollback gates and a newly accepted measurement packet. A compiler optimizer specializing ordinary callbacks at closed provider calls is another separate compiler task; no compiler change is authorized here. Neither option was silently implemented.

The current 13-module candidate scope permits private trusted provider/cache/query specialization with original headers and callback bytes retained. It does not permit rewriting protected application callbacks, bypassing their invocation, Data-only substitution or changing Bend compiler lowering. Further provider optimization can still be legitimate within that scope; claiming elimination of these callback constructions needs one of the explicit follow-ups above. No production candidate, ECS law/proof, dependency, timing or speed claim results from this experiment.
