# Occupancy and memory instrumentation contract

Status: implementation contract for #20, not executed occupancy evidence. The current Readers adapter reports physical occupancy and stored positions as unavailable. No S-INTEGRATE source or read-only TS reference is changed by this document. Instrumentation belongs in a separately frozen candidate overlay, with a matching diagnostic reference copy where private TS state must be observed. No universal proof, production API or threshold is approved.

## Separate measurements

1. **Functional/timing replay:** actual authored operations, complete observations and fresh reference checks; no additional reader invocations, drains, frame advances, barriers or skipped callbacks. Descriptor construction is outside the interval on both implementations. Seven fresh rotated repetitions require a fresh complete semantic gate for the same source closure and case first. A failed prerequisite or repetition gets an explicit failure, never a ratio filled from older evidence.
2. **Occupancy replay:** the identical input/operation sequence plus owner-preserving snapshots at the boundaries below. This separately labelled diagnostic replay may traverse logs, slots and pending commands; its cost is not silently mixed with old timing samples. If counters are later included in a timed subject, freeze that subject and account for instrumentation on every backend.
3. **Process RSS replay:** identical warmup, actual workload and full output validation, using the clean launcher described below. Physical entry counts are separate from KiB; neither is an allocation count.

## Required records and actual sources

A checkpoint carries `schema`, actual world identity, workload/count, actual iteration, phase, tick and frame. It also distinguishes unregistered (`null`) from registered-at-zero. Every numerical field comes from actual owned state or an explicitly identified public observation, never an expected formula or a final-drain assumption.

## Boundary coverage and peaks

Record after setup and initial registration; immediately before and after each invoked system; before finish and after success/failure; after every staged append for transaction peaks; immediately before/after publication and queue transfer; immediately before/after every explicit barrier; immediately before/after each frame trim; before/after skip; and before/after the final authored read/drain. Entry-by-entry append peaks may be maintained by exact counters at the actual mutation hook, but counters require independent traversal checks on finite controls and source provenance. Do not infer a transaction peak from the post-commit empty staging list or a command peak from an already-flushed world.

For Readers, retain the exact 64 iterations: spawn + barrier, update + Fast + Slow every fourth iteration, remove/despawn + barrier. The same Fast/Slow identities remain registered. Record source order explicitly when publication and frame trimming share a dispatch. A successful completion advances both stored positions; failure preserves them but first invocation registration can remain; skip advances only an already-registered stream position. Instrument these actual transitions rather than manufacturing expected cursor records.

Report maxima separately for retained values, retained batches, holder count, pending commands, staged commands, staged Pings, inverse entries and mark entries. Also report boundary values and the checkpoint where each maximum occurred. Component added/changed marks are persistent row metadata, not removal log occupancy. A final empty logical delivery does not imply zero retained batches, zero lifecycle records, no registered holders or discarded marks. Do not add an extra frame or reader call merely to force zero.

## Controls before trusting occupancy

Use actual finite executions that distinguish: one Ping publication batch from several singleton batches; whole-batch Ping overflow from individual lifecycle trimming; a slow holder from two equal-position independent holders; late registration from old dropped history; failed read/retry from success; skip from lifecycle advancement; staged versus published commands; earlier committed commands versus discarded failed commands; and empty unread delivery with nonzero retained physical records. Include nominal schema/world identity in records.

Counter/inspection mutations must be detected for an omitted rear list, stale cached size, lost holder, swapped cursor kind, ignored `registeredAt`, staged-as-pending substitution and a hard-coded final zero. Positive and negative instrumentation must preserve the same actual callback trace as an uninstrumented run. No occupancy inspector may call `begin`, `complete`, `skip`, `frame`, `trim` or a public reading system merely to obtain a metric.

## Common corrected RSS protocol

Use the separately compiled clean C launcher from `s-integrate/measurement-samples-rss-launcher.c`, copied byte-identically into a frozen measurement package if needed. The outer observer starts a process group and enforces five seconds. The exec-reset launcher forks from its small address space, execs the actual workload and collects that child's Linux `wait4.ru_maxrss`. Its own inherited high-water mark and the outer observer's wait4 result are diagnostics only. Before workload samples, reproduce the small-child controls with a large retained observer heap; `/bin/true`, empty Node and a touched allocation must not all acquire the observer's floor.

Pin launcher source/executable, compiler/Base, generated Native/JS, Node, workload/reference/validator closures, inputs, affinity, timestamps and commands. Native is O3, one worker, GPU off; JS/TS share Node and CPU5. Compile limits remain separate (codegen 30 seconds, clang 120 seconds); checker and each whole runtime group remain five seconds. Record overlapping workload processes when known; affinity does not establish exclusive machine isolation.

RSS includes child startup/imports, warmup, fresh setups, operation loops, retained observation snapshots, serialization, runtime/allocator/GC state and child-owned validation. Exclude the launcher's own peak. Keep seven raw samples and min/median/max only for complete validated sets; preserve deadline failures without replacement. Old contaminated readings remain withdrawn and old timing ratios remain historical. This protocol cannot establish component allocation counts, production memory acceptance or approved numerical performance thresholds.
