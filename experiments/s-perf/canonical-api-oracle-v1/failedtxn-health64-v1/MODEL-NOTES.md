# FailedTxn Health64 source-derived oracle

This leaf models the finite first64 Health scenario from the exact held source closure recorded in `HEALTH-SOURCE-FREEZE.json`. It retains the complete streamed stdout, all four boundaries per iteration, all schedule records, Local and reader owners, full physical World fields, and pre-finish transaction observations. This is a finite source-derived oracle; it is not a universal proof, law approval, backend qualification, or numerical performance claim.

The model follows the source's actual `WI.create` path twice in one process. `world-namespace.c` and `world-namespace.js` each start at namespace 1 and monotonically advance, so warmup is namespace 1 and measured is namespace 2. `health-driver.warmup_created` finishes the complete warmup `health-stream.write` before it calls the measured creation continuation. The model creates fresh ECS/allocator state for each World while retaining the process namespace lineage.

The nominal Health payloads are derived from the pinned dense Health types and this source closure. Each seed entity has `Vitals` with four `levels`, `reserve=9`, and `class=2`; indices divisible by three also receive `Armor` with four `layers` and `grade=3`; indices congruent to one modulo three receive `Tracked{group=8}`. `HealthLedger` starts with totals `[0,101,102,103]` and epoch 4, and its sibling service slot holds one `Recorded Audit`. The model observes these fixed nominal payloads only; it makes no general claim about arbitrary affine `Type` payloads or cross-schema access.

The frozen callback source writes one `Vitals` value for A and two for B. A increments the first level by one. B writes first-level values based on the original payload plus ten and plus thirty, so the second write is the committed value. A increments the Ledger first total by one; B increments it by one hundred. The first B attempt returns `Failure{7}` after staging its command and event and making its Audit service request. The transaction rollback restores Vitals, Ledger, and the pending spawn allocation while retaining the host-side clock advancement, the actual returned failed handle in the frame, the separate Audit service effect, and the Local capture update. B's retry uses the same ordinary reader provider and commits; the source's retry and barrier order determines the actual full handle generations and raw command application order.

Reader timing is modeled from the frozen ordinary mixed-reader path. Seed application leaves the World clock at 107. The route tick begins at zero while the reader failure metadata starts from that World clock. At each attempt synchronization ingests at `max(1, routeTick, failureTick, worldClock)`, advances the World clock and route tick once, and prepares at the new route tick. A callback failure does not commit either the event cursor or the ordinary registry cursor; preparation's missing-position activation remains. Publications has its own provider and cursor. The model retains full tick batches, registered reader positions, both cursors, route/failure ticks, staged and committed event values, and the complete provider render.

Every operation is derived from the frozen Health call graph and pinned core APIs: actual full reservation handles flow into pending lookups, failed-handle queries, retry state, and disposal; all three columns are rendered; service and Ledger owners remain separate product fields; schedules apply the explicit barrier before disposal. Boundary owners use the source's registered-owner projection, while the final owner projection includes the full accumulated call frame. Lists retain the source's cons order and `Base.List.show` comma-space framing. `health-stream.write` emits final frame calls, boundaries, and schedules in ordered chunks; the model preserves the exact concatenated record order and line endings.

The Python implementation began from the already source-corrected finite Motion64 model's physical/runtime structure. That reuse is limited to behaviors verified against this Health freeze's same core and operation order: allocator transitions, column stamps, ordinary event-reader clock/cursor behavior, schedule/barrier sequencing, and host namespace lineage. Health payload values, nominal field-preserving writes, JSON and physical renderers, access keys, and the complete Health stream are separately derived from the Health-specific frozen sources. No Health candidate backend output was read or used to derive this expected stream, and this worker did not compile or execute a backend. Earlier task history records that a broad search incidentally surfaced a few historical evidence snippets; those were discarded and did not inform expected derivation. This documents actual oracle scope rather than claiming code or historical-output blindness.

Validation performed before any Health backend output existed: Python syntax compilation; source-derived invariant self-checks for seed payloads, clocks, cursors, failed rollback, retained Audit/capture, event visibility, full-key allocation/reuse, and disposal; and two complete renders compared byte-for-byte with one another.
