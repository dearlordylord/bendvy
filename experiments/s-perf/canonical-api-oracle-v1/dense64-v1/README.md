# Independent canonical Dense64 semantic oracle

Source `c8e9ded18` in the canonical consumer worktree supplies two separate IO
entries. Each is bound to its complete 58-Bend import closure and two namespace
sidecars in the per-schema `SOURCE-BASIS.json`. Every reached core body equals
root `74a44d552`. Source checks are retained by the consumer author: pure modules
pass; the IO hosts report only three expected foreign definitions. This oracle
was derived without executing either consumer or reading consumer output.

`model.py` evaluates the actual deferred reservations, FIFO population, registered
ordinary traversal and detached final query. It renders every source-defined
field: 128 allocator slots, all physical Column trees and ordered stamps, resources,
pending constructor order, World metadata, actual Registry/clauses, 4,096 row
results, 64 audit totals/statuses and all 64 logical rows. It also renders the
complete physical World after the detached query. The report's final newline and
`IO.print` newline are both preserved. No normalization, hash-only physical
projection, prepared-column sentinel or callback execution is used.

The population writes Main64, Aux22 and Flag21, advancing the clock to107.
Each of64 ordinary calls then performs64 full Main reads/writes and64 full Ledger
reads/writes in row order. Only the component writes advance this clock, yielding
4203 and the same successful Registry cursor. Transaction inverse callbacks are
opaque and discarded through the actual successful finish; no retained Tx is
invented at the checkpoints.

`shared.py` independently derives the original logical workload. Both final-state
and all64 audit hashes match the existing pinned bevy-ts3040 receipt and exact
adapter source. That receipt validates complete logical values internally but
retains hashes and first/last samples rather than full raw final rows. Reuse is
limited to those exact assertions and inputs. Canonical provisioning and detached
inspection do not claim the TS Seed/Dump System registrations, ticks or physical
allocator representation. There is no timing or performance qualification here.

Reproduce a complete report with `python3 model.py Motion` or `python3 model.py
Health`; `python3 model.py --self-test` checks the finite operation model.
`verify.py.source` verifies pins, existing collector import closure, both raw/gzip
files and isolated Python reproduction. It never launches Bend, Node or a backend.
