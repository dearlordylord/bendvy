# Canonical runtime Dense correctness

The ordinary Motion and Health consumers read count and iterations through `IO.args` and `U32.read`. Those parsed values feed entity provisioning and the actual update loop. Each uses canonical declarations, public ordinary systems, owned component/resource capabilities, and WorldIO. The callback retains the authored per-row Main get/sum/set followed by Ledger get/set; resource writes are not aggregated outside the row.

The current candidate qualifies counts 64, 256, and 1024 with 64 iterations for both schemas on stock JS and Native. Twelve roles pass complete independently derived reports. Each schema's 1024 compilation produces the same JS/native artifacts subsequently run with 64 and 256; those consumer-only receipts pin the original producer receipts, artifacts, source, tools, resources, and evolving guards. This is correctness evidence, not a timing comparison.

Reports retain every logical row and iteration audit, full physical arrays and lifecycle stamps, allocator slots/free/order, resources, registry/cursor, reservations and returned owners. Pending observations expose count and ordered Raw/Observed constructors; opaque callback identities and captured payloads are not directly observed. Reservation order and complete post-barrier rows/stamps expose their actual FIFO effects.

The source-only independent model preserves the logical callback work shared with the pinned TS adapter. Canonical physical clocks, owners, and registration metadata are modeled independently without normalization.
